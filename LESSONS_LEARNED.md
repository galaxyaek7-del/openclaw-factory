# 📚 Lessons Learned — Day 09

Seven lessons from the Niche Safety Filter build-out (compliance gating, process hygiene, and the Butter Compliance naming collision). See [`NICHE_SAFETY_FILTER.md`](./NICHE_SAFETY_FILTER.md) for the system this work produced, and [`OpenClaw_Brain/19_Lessons_Learned/`](./OpenClaw_Brain/19_Lessons_Learned/) for this project's other established lessons — a placement note on why this doc lives here instead is at the bottom.

### 1. Zombie servers lie about test results

A `server.js` from a previous session held port 3000. Windows let a newly started process print `"listening"` while incoming requests kept routing to the old, already-bound process underneath it. The first round of compliance tests silently ran against unpatched code and reported a false pass.

**RULE:** Before any test, run `netstat -ano | findstr :3000`, identify and kill any stale PID actually holding the port, and confirm the PID you're testing against is the one you just started.

### 2. Duplicate background processes create race windows

Two `factory_loop.js` processes ran concurrently for roughly two days (PID 2232 since 07-06, PID 24652 since 07-08). Proof was in the log: paired entries 20ms–5s apart, tick after tick. Both processes were capable of firing the same "missing book" healing action in the same window.

**RULE:** Any long-running background process needs a PID lockfile guard that refuses to start a second instance while one is already alive (now implemented in `factory_loop.js`).

### 3. An endpoint that "accepts" a payload may ignore it

`/api/scout/run` reads nothing from `req.body` — it always invents its own brief via Groq (or a hardcoded fallback). Tests designed around POSTing a `niche`/`title` field proved nothing about this route's actual behavior; the posted values were silently discarded.

**RULE:** Read the route's full body — every line — before designing a test around what you assume its payload does. What a route is *documented* to accept and what it *actually reads* can diverge.

### 4. One gate is not enough — find every spawn site

Gating `/generate-book` felt complete after Task 2, but `/api/scout/run` was still spawning `book_generator.py` directly and producing real, publishable PDFs completely ungated (Task 8). A third spawn (`/api/trends` → `runQualityGate()`) was writing unfiltered niche names straight to `OPPORTUNITIES.md`, a human-facing dashboard file.

**RULE:** Before declaring a gate "done," grep every `spawn`/`exec`/file-write/publish call site for the same script or resource. The audit *is* the deliverable — a single gated route is not evidence the surface is covered.

### 5. Verify a name is free before you claim it

"Butter Compliance" already meant the $30 pricing floor (`CONSTITUTION.md` §16, `self_awareness.js`'s `getButterCompliance()`) before this content-moderation filter was named the same thing in Task 1. Eight tasks shipped code, tests, and near-final documentation under the colliding name before it was caught — during a documentation pass, not during the original build.

**RULE:** `grep`/search the codebase and its knowledge base for a term before adopting it as a new concept's name, not after. Executive Directive V3.0: "Evidence before assumptions."

### 6. Windows silently corrupts Arabic on stdin/stdout

Python defaults `sys.stdin`/`sys.stdout` to the platform codepage on Windows — `cp1252` on this machine, not UTF-8. Arabic blocklist keywords piped from `server.js` into the Python filter were silently mangled before any keyword matching ran, so the filter would have failed to catch Arabic scam terms entirely if this had shipped unnoticed.

**RULE:** Force UTF-8 explicitly on any cross-process text boundary (`sys.stdin.buffer.read().decode('utf-8')`, raw UTF-8 bytes on the way out) — never rely on a subprocess's default text-mode encoding, especially on Windows.

### 7. `git add -A` is a scope violation

A requested `git add -A` would have swept roughly 19 unrelated files into a commit whose message described 4. That included `.claude/settings.local.json` (local tool config), four `__pycache__/*.pyc` binaries, several factory-log/data files churned by the running loop, and a stray test-artifact PDF generated by an earlier task's own testing.

**RULE:** Stage only the files the current task actually produced. Name them explicitly in `git add`; never rely on `-A`/`.` to "catch everything," even when explicitly asked, without first checking what "everything" currently contains.

### 8. LLM ceiling isn't always the model — sometimes it's the ask

`llama-3.1-8b-instant` produced Publishability 3/10 on a full-book single-call generation. Swapping to `llama-3.3-70b-versatile` with a 46% larger token budget produced Publishability 1/10 — worse on the metric that matters most. Wordcount barely moved (972 → 998 despite the larger budget).

**RULE:** When output quality is capped, test whether the PROMPT pattern is the ceiling before assuming the MODEL is. Structural demands ("generate a full book, N chapters, K words each, this exact heading format") compress LLMs into generic mode. Chunked generation with independent context per chunk outperforms single-call generation of the same total length.

### 9. A log's volume is not evidence of real activity

`factory_loop.js`'s Golden Hunter Bridge logged 105 "attempted" dry-run entries over 4 days for the exact same niche at the exact same score — each entry individually honest (a real re-evaluation did happen), but the aggregate read like days of active market search when it was really a static file being re-read on a timer. Caught only by diffing entries against each other, not by reading any single one.

**RULE:** A counter or event-log growing over time is not proof that the underlying signal is changing. Before trusting "N events happened," check whether N distinct *states* happened, or the same one repeated.

### 10. A category-level bonus can invert a per-item quality gate

`profit_oracle.opportunity_score()`'s tier1 path added a fixed, tier-wide bonus (`automation_potential`/`long_term_value`) meant to reflect Tier 1's strategic value — but combined with tier1's highest multiplier, that fixed bonus alone cleared the acceptance floor regardless of the actual item being scored. A single-character niche ("x") scored 76.4 and "passed" a gate meant to be *stricter* than the one below it, which correctly rejected the same input.

**RULE:** When a formula adds a category-wide constant on top of a per-item signal, compute the *effective* per-item bar that constant leaves behind for each category — don't assume "we added a bonus for the important tier" and "the important tier is harder to pass" are the same claim.

### 11. Trace the real call path before "fixing" a suspected bug

Two findings looked like real bugs from a first read of the code alone: "three competing scoring systems" and "shared .md files with no file lock." Tracing every actual caller both times changed the diagnosis — the "competing" scores turned out to be an intentional 3-stage funnel (`run_oracle()` only ever calls the unweighted scorer; the stricter gate applies once, at the final production step), and the "race condition" turned out to be confined to a manual demo script, not the live automated path. Acting on the first-read diagnosis in either case would have meant "fixing" something that wasn't broken, or over-building a defense against a risk that was much narrower than it looked.

**RULE:** Grep every real call site of a function before proposing to change it. What a function looks like in isolation and what it's actually used for can disagree.

### 12. A tool's export and import commands are not the same risk class

n8n's CLI has both `export:workflow` (reads the local database) and `import:workflow` (writes to it). Running export while the n8n server process was already live and serving traffic was safe — confirmed by checking both n8n and `server.js` kept responding normally afterward. Import against the same live database was judged too risky to attempt without authorization, since a concurrent write against a database the server itself might touch mid-request could corrupt workflows already in production use.

**RULE:** For any CLI tool with separate read/write subcommands against a database a live service also owns, treat them as different risk tiers even when they're documented side-by-side and look symmetric — a safe diagnostic read does not imply a safe write.

### 13. One real data batch is cheaper than building the pipeline first

Before writing `market_hunter_tier1.py`, one real search batch against Hacker News + GitHub (both free, keyless APIs) was run through the *existing* scoring function first. It surfaced that the scorer itself was structurally blind to real market signal (HN points, GitHub stars) — a finding that would have been much more expensive to discover after building an automated collection pipeline on top of it.

**RULE:** Before automating a new data-collection pipeline, run one manual batch of real data through the scoring/gating logic that will consume it. If the existing logic can't meaningfully use good real data today, more automated data won't fix that — the gate needs work first, not the pipe.
