## `market_hunter.py` — The Golden Hunter

Per CONSTITUTION.md §19: consults the Knowledge Brain **first**, always, before proposing anything.

```
_generate_candidates()      curated seed categories (planners, SVG templates, trackers...)
                             × profit_oracle's own seasonal calendar + subniche qualifiers
     ↓
_check_knowledge_brain()    CRITICAL gate, checked before scoring, not after:
                              1. REJECTED_NICHES.md (factory_loop.js's circuit breaker) → hard skip
                              2. QUARANTINE.md (inspectors.py's rejection history) → hard skip
                              3. books/_generation_log.jsonl (duplicate check) → hard skip
                              4. OpenClaw_Brain/ keyword search → advisory only, logged not blocking
     ↓
profit_oracle.score_opportunity()   the single scoring authority — market_hunter never re-scores
     ↓
verdict != SKIP (score ≥ 60)?  → appended to OPPORTUNITIES.md, tagged "market_hunter"
     ↓
profit_oracle.run_oracle()    re-run automatically so GOLDEN_OPPORTUNITIES.md stays the one
                               authoritative, single-writer file (market_hunter never writes it directly)
```

**Why market_hunter doesn't write `GOLDEN_OPPORTUNITIES.md` itself:** that file already has one writer (`profit_oracle.run_oracle()`). Giving market_hunter a second, parallel writer for the same file would violate Constitution §2 (one source of truth) and risk the two disagreeing. Instead, market_hunter feeds the *same* intake file (`OPPORTUNITIES.md`) that n8n's `/api/trends` was always meant to feed, then triggers the existing writer.

**Where the guaranteed $30+ price actually lives:** `GOLDEN_OPPORTUNITIES.md`'s own price column is `profit_oracle`'s rougher `recommended_price` heuristic (not guaranteed ≥ $30). market_hunter's own log (`market_hunter_runs.log`, surfaced via `GET /hunter`) carries `recommended_butter_price` — `profit_oracle.butter_price()`'s guaranteed $30–$100 value — for anyone who specifically needs the Butter-tier-guaranteed number.

**Cadence:** `factory_loop.js` runs `market_hunter.py --run` once per calendar day (gated by `market_hunter_runs.log`'s last timestamp), not every 10-minute tick — the curated candidate list doesn't change fast enough to justify scanning it more often.

## What "GOLDEN" actually means — read before trusting a score

`profit_score` is a blend of four signals, only some of which are real data:

| Signal | Real or estimated? |
|---|---|
| Seasonality (in-season keyword match) | **Real** — actual current date vs. a keyword calendar |
| Search volume | Estimated — word-count specificity heuristic, no live API |
| Trend momentum | **Always a neutral 50** — no Google Trends connection exists anywhere in this factory |
| Competition (if a saved `niche_reports/` file matches) | **Real** — reuses `niche_validator_v2.py`'s Amazon research |
| Competition (no saved report) | Estimated — word-count heuristic |
| Price tier / margin | Estimated — keyword-tier heuristic, now also feeds `butter_price()` |
| Execution fit | **Real** — grounded in the actual fact that only `book_engine` is active |

A GOLDEN (80+) score is a genuinely useful signal, but it is not the same claim as "Google says this is trending" — nothing in this factory has ever made that claim with real data behind it. See [19_Lessons_Learned](../19_Lessons_Learned/) for why this distinction matters (a recurring theme: never fabricate a data source that doesn't exist).

## How to regenerate this intelligence

```bash

python market_hunter.py          # demo mode: 1 GOLDEN + 1 SKIP + 1 Brain-blocked sample

```
