# ADR-037 — تشخيص n8n الفعلي: لا حاجة لـ20 قسماً جديداً، إصلاح صغير + تفعيل

**التاريخ:** 2026-07-15
**الحالة:** تشخيص مكتمل (قراءة فقط، `n8n export:workflow --all` — عملية آمنة، لا كتابة على القاعدة، تأكَّد استمرار عمل n8n وserver.js بلا انقطاع بعدها).
**يُنفِّذ:** "EXECUTIVE ORDER"'s تعليمة صريحة: "إن منع التوثيق/الإعداد الأتمتة، شخِّص المشكلة وجهِّز كل ما يمكن إنجازه بلا تجاوز الأمان، وأبلِغ بوضوح عن الخطوة اليدوية المتبقية."

---

## الحقيقة الكاملة (5 workflows موجودة فعلاً، لا صفر كما بدا)

`n8n`'s REST API يحتاج تسجيل دخول غير متوفر (401) — لكن `n8n export:workflow --all` (عملية قراءة صرفة من القاعدة المحلية، لا كتابة، لا تعارض مع الخادم الحي) كشفت الحالة الفعلية:

| الاسم | الحالة | التشخيص |
|---|---|---|
| `My workflow` | غير نشط | مثال n8n الافتراضي الفارغ (Google Drive) — غير متعلق بالمصنع، يمكن حذفه |
| `Openclaw_Sensing_Engine` | **غير نشط** | **مكتمل وسليم بنيوياً** — `Schedule Trigger → HTTP Request → XML → Split Out → HTTP Request1 → Edit Fields` كلها متصلة بشكل صحيح (تأكَّد من `connections` في التصدير) — نفس الخلل الذي أُصلِح سابقاً (المُشغِّل كان منفصلاً) **لا يزال مُصلَحاً**. الفجوة الوحيدة: **غير مُفعَّل** |
| `02_Sales_Poll` | **غير نشط** | **مكتمل وسليم** — `Schedule Trigger → HTTP Request` يستهدف `http://localhost:3000/api/sales/poll` (endpoint حقيقي موجود فعلاً). الفجوة الوحيدة: **غير مُفعَّل** |
| `01_Market_Scout` | غير نشط | **ناقص فعلياً** — عقدة `HTTP Request` بلا `url` مُعرَّف إطلاقاً (فارغة) — حتى لو فُعِّل، لن يفعل شيئاً |
| `00_CEO` | غير نشط | **ناقص فعلياً** — عقدة `Execute Workflow` بمرجع غير محلول (`value: "="` — تعبير غير مكتمل، لا معرِّف workflow حقيقي) |

## القرار

**لا بناء لـ20 قسم/workflow جديد.** التوجيه نفسه يطلب "لا تُنشئ workflows مثال — ابنِ منصة إنتاج حقيقية". لا يوجد منطق أعمال حقيقي خلف أغلب الأقسام المطلوبة اليوم (Customer Support: صفر عملاء؛ Backup: git يغطي هذا فعلاً؛ Security: `safety_filter.py` يعمل داخل العملية نفسها لا كـworkflow خارجي؛ Reporting: `factory_loop.js`'s Weekly Reports تفعل هذا فعلاً). بناء أصداف فارغة لهذه الأقسام هو بالضبط "أمثلة" لا "منصة إنتاج حقيقية" — نفس مرض الاحتفالية المُشخَّص اليوم مبكراً، بحجم أكبر.

**ما يستحق فعلاً:** الأتمتة الحقيقية موجودة أصلاً (Sensing Engine، Sales Poll) بل ومصمَّمة بتسمية تنظيمية بالأقسام (`00_CEO`, `01_Market_Scout`, `02_Sales_Poll`) من جلسة سابقة — لم يكن الفراغ في التصميم، بل في اكتمال التنفيذ والتفعيل.

**لم يُحاوَل إصلاح `01_Market_Scout`/`00_CEO` بكتابة JSON يدوياً واستيراده.** تعديل معاملات عقدة (URL، مرجع workflow) عادة عملية واجهة مرئية، وكتابة JSON خام لعقدة n8n بلا اختبار استيراد آمن (نفس مخاطرة CLI's import ضد قاعدة حية) يحمل خطر إنتاج JSON غير صالح يكسر workflow قائم. هذا **يُترَك للخطوة اليدوية أدناه**، لا لتخمين بلا تحقق.

## الخطوة اليدوية المتبقية (بوضوح، كما طُلِب صراحة)

1. تسجيل الدخول إلى `http://localhost:5678` (الرئيس فقط يملك بيانات الدخول).
2. **تفعيل** `Openclaw_Sensing_Engine` و`02_Sales_Poll` — كلاهما جاهز فعلياً، يحتاج فقط ضغطة "Active" في الواجهة.
3. **إصلاح** `01_Market_Scout`'s عقدة `HTTP Request` — تعيين `url` إلى `http://localhost:3000/api/scout/run` (الأنسب حسب اسم الـworkflow والـendpoint الحقيقي الموجود فعلاً في `server.js`).
4. **قرار** بخصوص `00_CEO` — هل هذا orchestrator حقيقي مطلوب (يستدعي workflows أخرى)؟ إن نعم، يحتاج تحديد أي workflow فعلياً يستدعيه؛ إن كان تجريبياً فقط، يمكن حذفه.
5. اختياري: حذف `My workflow` (مثال n8n الافتراضي، بلا علاقة بالمصنع).

## الأثر

- ملف جديد: هذا الـADR.
- **لا تعديل على أي workflow n8n فعلياً** — القراءة فقط، مؤكَّد أن الخادمين (n8n وserver.js) يعملان بلا انقطاع بعد التصدير.
- لا ملفات export مؤقتة أُبقيت في الريبو (كانت في مجلد temp خارج المشروع).
