# ADR-135 — Global Trust & Resilience Layer

**Date:** 2026-07-29
**Status:** Adopted.

---

## The directive

"EXECUTIVE DIRECTIVE — GLOBAL TRUST & RESILIENCE LAYER": Galaxy Forge must behave like a mature international company, not an AI script. Ten permanent systems requested — Company Self-Diagnosis, Safe Mode, a Global Policy Engine, Reputation Protection, Human Trust (fact/estimate/unknown/recommendation labeling, never mixed), Decision Memory, Resilience Tests, Continuous Improvement, Founder Protection, and a long-term "durability over decades" objective.

Three parallel research passes mapped every priority against what this factory already has. Verdict, same pattern as the two prior directives this session: most of it was already substantially built (Executive Intelligence Core, Autonomous Evolution Engine, Global Commercial Hardening) — the real work here was closing named, scoped gaps and resolving one real architecture conflict directly with the founder.

## Round 0: a real regression, found and fixed before any new feature work

Research surfaced that `commercial_execution/pipeline.py::run_publish_pipeline()` called `distributor.distribute()` without threading a `protection_state_path` — every real-mode (`dry_run=False`) call anywhere, including 5 real-mode tests in `tests/test_commercial_execution.py`, silently shared the real `data/publish_protection_state.json`. Confirmed: that real file had already accumulated fake "paddle" publish counts from a prior test run, and the full regression suite had already failed once from it (a real-mode test tripped the real min-publish-spacing cooldown left behind by an earlier test in the same process). Fixed: the parameter now threads through; the polluted real file was deleted (100% test-injected data, zero real founder/customer action behind it) so it regenerates honestly empty; the fix was verified stable across 3 consecutive full test runs before any Round 1 work began.

## Resolved architecture conflict: Founder Protection vs. autonomous publishing

Priority 9 literally asks for founder approval before "marketplace publishing" — directly in tension with this factory's own deliberate, already-shipped design: a credentialed, healthy-status arm publishes autonomously, with no per-item founder click (`commercial_execution/approval_gates.py`, `FACTORY_LIVE_PUBLISH`). Put to the founder directly. **Explicit choice: keep autonomous publishing for proven arms as-is; add a real new approval gate only for genuinely novel or elevated-risk publishes.** This is Round 4 below — everything else in Founder Protection was already satisfied (research confirmed: no auto-executing financial/deletion/infra/integration path exists anywhere in this factory).

## What was built

**Round 1 — Self-Diagnosis: real health trend tracking.** `lib/health_trend.js` (real recording — `factory_loop.js`'s tick already fetches a real `GET /health` status every cycle via `diagnose()`; this appends it to `data/health_snapshots.jsonl`, the same append-only convention every ledger here uses) + `health_trend.py` (the Python-side mirror, same "same real computation, reimplemented per language" precedent `executive_score.py`'s `_dual_inspection_pass_rate()` already established). `detect_health_degradation()` is a real, disclosed mechanical heuristic — two narrow signals (strictly-worsening, sustained-unhealthy) over real recorded history, never a fabricated ML-style prediction. `tool_intelligence/proposals.py` gained a 6th dynamic generator, `_health_degradation_proposal()`.

**Round 2 — Safe Mode: per-subsystem isolation.** `safe_mode.py` (new) generalizes this factory's existing per-arm circuit breaker (`channels/base_arm.py`, `channels/publish_protection.py`) to three real, named subsystems: `ai_generation`, `market_intelligence` (their own independent flag, atomic-write state file) and `marketplace_publishing` (deliberately **not** given an independent flag — its real signal already exists and is load-bearing: `channels/publish_protection.py`'s own global emergency stop, read directly rather than duplicated). Mission Control gained a read-only `safe-mode-status` panel and founder-only `mark-subsystem-unstable`/`clear-subsystem-unstable` actions.

**Round 3 — Global Policy Engine: Constitution + ToS awareness.** `executive_quality_gate.py` gained `check_constitution_alignment()` — a real, mechanical cross-reference confirming which of `CONSTITUTION.md`'s principles (§16 Butter Principle, §17 Dual Inspection) are actually backed by real evidence already present for a given decision. Informational only (`status: "INFO"`), never added to `REJECT_IF_FAIL` — a real citation of already-running checks, not a new judgment engine. `check_platform_tos_awareness()` honestly returns `UNKNOWN`, always, today — confirmed by repo-wide search: zero platform Terms of Service text is parsed or enforced anywhere in this factory. Disclosed as a real, named gap for manual human review before a first real publish to any platform, never a fabricated PASS.

**Round 4 — Founder Protection: new-platform / high-risk publish approval.** `channels/publish_protection.py::check_publish_allowed()` now also blocks: (a) a genuinely new arm's first real publish — `KNOWN_PROVEN_ARMS` (`gumroad`, `etsy`, `payhip`, `paddle`, the arms with a real track record predating this module) are exempt, keeping their existing autonomous behavior unchanged, per the founder's resolved choice above; (b) any publish whose computed `risk_score` crosses a real high-risk threshold (70). Two new founder-only, single-purpose clearances: `approve_first_publish()` (permanent, cleared for good the moment a real success is recorded) and `approve_elevated_risk_publish()` (single-use — consumed by the very next real attempt, whatever its outcome, never a blanket future approval). Exposed as `approve-first-publish`/`approve-elevated-risk-publish` Mission Control actions.

**Round 5 — Human Trust: real/estimated component tagging.** `profit_oracle.py::opportunity_score()` gained a parallel `components_basis` dict — `market_demand`/`competition_favorability` are `"real"` only when `external_signal` (real HN/GitHub engagement data) was actually given, `"estimated"` otherwise (a keyword-based heuristic); `profit_potential` is always `"estimated"` (a pricing-tier calculation, never live market data); `automation_potential`/`long_term_value` are always `"estimated"` (fixed per-tier policy constants, never per-niche signal). Read-only metadata — the real `components` values and `accepted` decision are provably unchanged.

**Round 6 — Decision Memory: linking real outcomes into company memory.** `decision_engine/types.py::Decision` gained optional `alternatives_rejected`/`expected_outcome` fields (additive, `None` for every decision recorded before they existed — honest, never backfilled). Research found the "actual outcome" recording mechanism already real and already wired (`decision_engine/feedback.py::sync_outcomes()` → `data/decision_outcomes.jsonl`, real-but-empty today, zero matched sales yet) — the actual gap was that this data was never linked into company memory. `knowledge_graph/build.py` now reads it and adds a real `Outcome` node with a `resulted_in` edge back to its `Decision` node, mechanically joined by `decision_id` — only for a real, matched outcome; an unmatched sale (`decision_id` is `None`) has no real decision to link to honestly, so it's skipped, never guessed. `evolution_queue.py`'s existing `mark_implemented()` note field is this factory's real "lessons learned" record — documented here as such, not duplicated with a second field.

**Round 7 — Continuous Improvement: customer-success framing.** `evolution_engine.py::build_evolution_report()` gained `customer_success_bottleneck` — reuses `tool_intelligence.proposals`' own already-real, already-customer-tied `_customer_funnel_proposal()` signal (fed by `customer_pipeline.list_pipeline_overview()`'s real stuck-request detection), framed explicitly as "the biggest real bottleneck to customer success" rather than computing a second, competing detector. Honestly reports none detected when it didn't fire (true today — zero real customer traffic).

**Round 8 — Reputation Protection.** Research confirmed no fabrication path exists anywhere in this factory (reviews/finance/analytics are all real-input-only, confirmed by repo-wide search for random-data generation in production code paths). `channels/publish_protection.py`'s existing rate/cooldown state already *is* the real anti-spam/anti-aggressive-publishing control — this round is documentation, not new code: recorded here rather than building a second, redundant mechanism.

**Round 9 — Resilience Tests.** `tests/test_resilience.py` (new) — a real, mocked fault-injection suite proving existing recovery code, never a live chaos system against real production data (this factory has no scheduler and no staging environment). Three genuinely new, cross-cutting integration checks that no single module's own unit tests already covered: (1) one arm's real simulated failure never blocks a healthy arm's real publish, and a later real success fully clears the failed arm's cooldown state (Constitution §7 Self-Healing, proven at the `distributor.py` fan-out level, not just inside one arm); (2) the same real corrupt-file input degrades to a safe default consistently across three independently-built modules (`factory_state.py`, `channels/publish_protection.py`, `safe_mode.py`) rather than being provably true for only one of them; (3) `recovery/startup_check.py`'s real classification path (HEALTHY / RECOVERING / fail-closed NEEDS_CONFIRMATION) end-to-end, including that the classification is actually persisted to `factory_state.json`, not just returned in memory, and that `resolve_recovery()` really clears it.

## Validation

New/updated tests: `tests/test_health_trend.js` (new, 8), `tests/test_health_trend.py` (new, 7), `tests/test_safe_mode.py` (new, 16), `tests/test_executive_quality_gate.py` (+9, Constitution/ToS checks), `tests/test_publish_protection.py` (+7, Founder Protection; 1 pre-existing test updated to reflect the new, intentional first-publish gate for non-proven arms), `tests/test_opportunity_score.py` (+5, `components_basis`), `tests/test_knowledge_graph.py` (+3, Outcome nodes/edges), `tests/test_evolution_engine.py` (+3, customer-success framing), `tests/test_resilience.py` (new, 11), `tests/test_mission_control_api.py` (+9, new dispatch endpoints), `tests/test_tool_intelligence.py` (+8, `_health_degradation_proposal()`), `tests/test_distributor.py`/`tests/test_commercial_execution.py` (isolation fixes for Round 0). 183 downstream tests re-verified clean after Round 4's behavioral change; full `tests/test_api_contract.js` (29/29) re-run clean after every Mission Control-touching round.

## What's still honestly Unknown / not built

`check_platform_tos_awareness()` stays `UNKNOWN` by design — no platform ToS is parsed anywhere, and this round explicitly declined to fabricate that check rather than build a real one under time pressure; a human must review a platform's real ToS manually before its first real publish. JS-side resilience fault-injection (a real Groq-outage retry/fallback test, a real corrupted-`finance_data.json`-via-HTTP test) is disclosed, not built this round: `server.js` has zero `module.exports`, so every existing JS test of its internals goes through a real subprocess-booting HTTP harness (`tests/test_api_contract.js`'s pattern) rather than a direct function import — extending that heavier harness for fault injection is real future work, not attempted here to avoid a shallow, rushed version. `data/decision_outcomes.jsonl` stays real-but-empty until a real sale is confidently matched to a real decision — the linking code is real and tested against injected fixtures, but has nothing real to link yet.
