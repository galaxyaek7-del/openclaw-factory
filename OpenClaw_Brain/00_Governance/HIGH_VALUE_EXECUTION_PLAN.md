## 0. لماذا هذا النموذج متماسك فعلاً (لا خيال هندسي)

`HIGH_VALUE_STRATEGY.md` §0 نبّه: "المدير التنفيذي (Claude)" ليس API مدفوعة داخل الكود. **نموذج المراجعة المعلقة يحل هذا التناقض تماماً** — لا يفترض استدعاءً آلياً لأي شيء: الرئيس يفتح **نفس** جلسة Claude Code (نفس الاشتراك المُستخدَم في هذه المحادثة)، يطلب المراجعة، وClaude Code يستخدم أدواته العادية (قراءة/كتابة ملفات، تشغيل سكربتات) لتحسين المسودة ثم **تشغيل سكربت آلي موجود فعلاً** لإكمال الفحص والتوزيع. **هذا حقيقي، مبني، ومختبَر حياً اليوم — لا اقتراح نظري.**

## 1. البنية المبنية فعلاً اليوم

```
pending_review/
  README.md          ← الاتفاقية الكاملة (شكل JSON، دورة الحياة)
  queue/              ← مسودات Groq خام، بانتظار المراجعة
  approved/           ← بعد التحسين البشري-Claude — جاهزة للمعالجة الآلية
  completed/          ← نجحت (published:true) — مؤرشَفة مع النتيجة الكاملة
  rejected/           ← فشلت الفحص بعد المراجعة — مؤرشَفة مع السبب
```

**`scripts/process_approved_drafts.py`** — الجزء الآلي بالكامل: يقرأ كل ملف في `approved/`، يستدعي `book_generator.py --json` (يُوجَّه تلقائياً إلى `generate_book_from_content()` الجديدة عبر وجود حقل `chapters`)، وإن نُشِر (`published:true`) يستدعي `distributor.py --json` بـ`dry_run:true` دائماً، ثم يؤرشف النتيجة في `completed/` أو `rejected/`. **لا يلمس** `book_generator.py`/`distributor.py`/`inspectors.py` — تنسيق بحت لأدوات موجودة فعلاً.

**`generate_book_from_content()`** (جديدة في `book_generator.py`, `ADR-022`) — تتخطّى Groq بالكامل، تأخذ فصولاً مكتوبة يدوياً، وتمرّرها لـ`create_ai_book()` الموجودة فعلاً (بلا تعديل)، ثم نفس الفحص المزدوج + السجل + قاطع الدائرة الذي تستخدمه `generate_book()`/`generate_printable()`.

**`gumroad_premium`** (اقتصاد جديد في `economics.py`/`config/economics.json`, `ADR-024`) — أرضية ربح $25، سقف واقعية سوق مستقل ($5/صفحة، سقف $50 للحزم القصيرة) — لا علاقة لـ`kdp_ebook`/`gumroad_digital` به.

### التحقق الحي الكامل (اليوم، dry-run فقط)

مسودة اختبار بنيوي واضحة التصنيف (`STRUCTURAL TEST DRAFT`, غير منتج حقيقي) وُضِعت في `approved/`، `process_approved_drafts.py` عالجتها:
- توليد PDF حقيقي عبر `generate_book_from_content()` (4 صفحات، غلاف AI حقيقي عبر `cover_designer_v2`).
- الفحص الفني: نجح بالكامل.
- الفحص التجاري: نجح — **`butter_price: "net $87.30 clears floor $25.00 (platform: gumroad_premium)"`** — يؤكد أن أرضية $25 الجديدة تعمل عبر المسار الحقيقي الكامل، لا اختباراً معزولاً.
- `published: true`، مُسجَّل في `books/_generation_log.jsonl`.
- توزيع `dry_run` عبر `distributor.py` — محاولة حقيقية، فشل آمن متوقَّع (لا توكن Gumroad).
- انتقل تلقائياً إلى `pending_review/completed/`.

**الحلقة الكاملة عملت بلا أي تدخل بشري إضافي بعد وضع المسودة المُحسَّنة في `approved/`.**

## 2. قناة الإشعار — مُصمَّمة، غير مبنية بعد (خطوة تالية صغيرة صريحة)

**التصميم:** إعادة استخدام **نفس نمط `NEEDS_ATTENTION.md`** الموجود فعلاً في `factory_loop.js` (يُنشَأ/يُحذَف تلقائياً بناءً على شرط) — خطوة جديدة `checkPendingReview()` في `runTick()`: تعدّ ملفات `pending_review/queue/*.json`، إن كانت ≥ 1 تكتب/تُحدِّث `NEEDS_REVIEW.md` (بنفس أسلوب `NEEDS_ATTENTION.md` — يُحذَف تلقائياً حين يفرغ `queue/`). **لم يُبنَ اليوم عمداً** — تعديل على `factory_loop.js` نفسه لم يكن ضرورياً لإثبات أن النموذج يعمل (أثبتنا ذلك بتشغيل `process_approved_drafts.py` يدوياً)، ويستحق دورة اختبار مستقلة قبل لمس الحلقة الحيّة.

## 3. ربط كل الأدوات بالنموذج — حالة كل واحدة اليوم بصراحة

| الأداة | علاقتها بالنموذج اليوم |
|---|---|

| `factory_loop.js` | **غير مربوط بعد** — الإشعار (`NEEDS_REVIEW.md`) مُصمَّم في §2، لم يُبنَ. لا شيء آخر في `factory_loop.js` يعرف بوجود `pending_review/` اليوم. |
