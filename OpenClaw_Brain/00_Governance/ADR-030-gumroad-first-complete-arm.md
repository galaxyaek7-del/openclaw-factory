# ADR-030 — Gumroad هي الذراع الأولى المكتملة 100%

**التاريخ:** 2026-07-15
**الحالة:** معتمَد. الكود مكتمل 100%. **النشر الحي معلَّق على قرار الرئيس (توكن حقيقي) — ليس نقصاً هندسياً.**
**يُنفِّذ:** توجيه الرئيس — "اختر أنت الذراع الأنسب... ذراع واحدة مكتملة + n8n يعمل آلياً."

## القرار: Gumroad

بين Gumroad/Payhip/Etsy، **Gumroad** هي الذراع الأولى المكتملة 100%.

## معايير الاختيار (كما طلب الرئيس) — لماذا Gumroad تحديداً

| المعيار | Gumroad | Payhip | Etsy |
|---|---|---|---|
| حجم الكود الفعلي (`channels/*_{arm,publisher}.py`) | 317 سطر | 156 سطر | 238 سطر |
| API موثَّق وحقيقي | نعم، REST v2، توكن بسيط | نعم (نظرياً، `config/channels.json`) | نعم (Open API v3)، لكن **يحتاج OAuth2 كامل + موافقة تطبيق جديد** (`channels/etsy_publisher.py`'s توثيقها الصادق) |
| تعقيد الحصول على بيانات الدخول | ضغطة واحدة في إعدادات الحساب | غير مُتحقَّق | تدفّق OAuth2 كامل + خطر رفض Etsy لتطبيقات جديدة (موثَّق في ADR-025) |
| get_sales (استطلاع مبيعات) | مُطبَّق ومُختبَر فعلياً (ADR-016) | غير موجود | غير موجود |
| إثبات تناسب مع Tier 2-3 | نعم — أول منتجين حقيقيين اليوم (2026-07-13) استهدفا Gumroad (`product_review_2026-07-13/01_gumroad_premium_guide/`) | جزئي (منتج 2 استهدف Payhip لكن عبر توزيع Gumroad-tier اقتصادياً) | لا |

**الخلاصة:** Gumroad هي الوحيدة التي يجتمع فيها: أبسط مسار حصول على مفتاح (لا OAuth)، أكبر كود ناضج موجود فعلاً، واستطلاع مبيعات مُختبَر مسبقاً — بلا أي عائق بشري هيكلي (خلافاً لـEtsy).

## "مكتمل 100%" — التحقق البند ببند

| المطلوب (توجيه الرئيس) | الحالة قبل اليوم | الحالة بعد اليوم |
|---|---|---|
| API integration كامل (لا dry-run فقط) | مبني بالكامل: `create_product`/`update_product`/`get_sales`/`list_products`، كل استدعاء حقيقي عبر `requests`، لا محاكاة | بلا تغيير — كان مكتمل بالفعل |
| رفع منتج + غلاف + وصف + سعر | عنوان/وصف/سعر/ملف PDF: نعم. **صورة غلاف: غير مُطبَّقة** — ولم تُضَف اليوم أيضاً | **فجوة مفتوحة، موثَّقة بصدق لا مخمَّنة (انظر أدناه)** |
| استطلاع مبيعات دوري فعلي | الكود موجود (`scripts/poll_sales.py`، `/api/sales/poll`) لكن بلا أي تشغيل دوري حقيقي — لا OS cron، لا خدمة تُبقيه حياً | **الآن دوري فعلياً عبر n8n** (`02_Sales_Poll` workflow، كل 4 ساعات، ADR-031) — بعد ضغطة تفعيل واحدة من الرئيس |
| معالجة أخطاء كاملة | حجب توكن من الأخطاء، أخطاء واضحة لكل نوع فشل، circuit breaker (`_consecutive_failures`)، **لكن صفر اختبار** لهذا الملف قبل اليوم | + إعادة محاولة (retry/backoff) للاستدعاءات الآمنة فقط (GET/PUT)، + 5 اختبارات جديدة (كان الملف بلا أي اختبار) |
| تحديث حالة المنتج تلقائياً | **موجود بالفعل ومكتمل** — `distributor.py` يسجّل كل محاولة (نجاح/فشل) في `data/sales_ledger.jsonl` عبر `channels/ledger.py`، بديل حقيقي لـ"published: true" الكاذب القديم | بلا تغيير — لم يكن يحتاج عملاً إضافياً |
| كل شيء موثَّق في ADR | — | هذا الملف + ADR-031 |

## الفجوة الوحيدة المتبقية في الكود: صورة الغلاف

بحث فعلي (WebSearch + WebFetch لـ`gumroad.com/api` و`help.gumroad.com`) **لم يُثبِت** المعامل/المسار الدقيق لرفع صورة غلاف عبر Gumroad API v2 — الصفحات المتاحة بلا مصادقة إما فارغة (JS-only) أو تطلب تسجيل دخول. **لم أُخمِّن معاملاً غير مؤكَّد** — هذا كان سيخالف نفس المبدأ الذي التزم به `channels/etsy_publisher.py` (توثيق صادق لما هو غير مؤكَّد، لا كود مبني على تخمين). الخطوة الصحيحة: التحقق ضد استدعاء حي فعلي بعد وجود توكن — لا قبل ذلك.

## العائق الوحيد أمام "أول بيعة حقيقية": ليس هندسياً

بموجب قيد الرئيس الصريح اليوم ("لا مفاتيح API خارجية بدون إذن صريح")، **لم يُطلَب ولم يُنشَأ** `GUMROAD_ACCESS_TOKEN`. `.env` يحتوي `GROQ_KEY` فقط. هذا يعني:

- كل كود الذراع **جاهز 100%** ومُختبَر (`load_token()` يفشل بوضوح `ConfigError` بدل تخمين أو تعطّل صامت).
- الخطوة الوحيدة المتبقية بين اليوم و"أول بيعة حقيقية" هي **فعل بشري خارج نطاق هذه الجلسة**: الرئيس يُنشئ/يملك حساب Gumroad فعلياً، يولّد Access Token من `gumroad.com/settings/advanced`، يضعه في `.env`.
- لا يمكن ولا يجب أن يقوم Claude Code بهذه الخطوة نيابة عن الرئيس — هذا بالضبط ما يحمي منه القيد الذي وضعه الرئيس نفسه اليوم.

**هذا ليس اعتراضاً على المهمة، بل توضيح لتعريف "مكتمل 100%":** الكود مكتمل بالكامل؛ "أول بيعة" معلَّقة على قرار عمل واحد بسيط من الرئيس (توكن)، لا على أي عمل هندسي متبقٍ.

## الأثر

- ملف مُعدَّل: `channels/gumroad_publisher.py` (retry/backoff للاستدعاءات الآمنة فقط — `create_product` لم يُلمَس، لتفادي احتمال إنشاء منتج مكرَّر عند إعادة محاولة POST غير idempotent).
- ملف جديد: `tests/test_gumroad_publisher.py` (5 اختبارات — الملف كان بلا أي اختبار).
- لا تعديل على `channels/gumroad_arm.py`، `distributor.py`، `channels/ledger.py` — كانت مكتملة بالفعل.
