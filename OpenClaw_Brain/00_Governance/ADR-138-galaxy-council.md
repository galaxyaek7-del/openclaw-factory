# ADR-138 — Galaxy Council (The Unified Executive Board)

**Date:** 2026-07-29
**Status:** Adopted.

---

## The directive

"EXECUTIVE DIRECTIVE — GALAXY COUNCIL (THE UNIFIED EXECUTIVE BOARD)": Galaxy Forge's intelligent modules must stop thinking independently. Create a Council of 10 named members (Strategic Intelligence Core, Market Intelligence, Production Intelligence, Customer Intelligence, Financial Intelligence, Security Intelligence, Resilience Intelligence, Innovation Intelligence, Executive Memory, Mission Control). Every important decision passes through the Council; each member produces `{Opinion, Confidence, Evidence, Risk, Recommendation, Founder approval requirement}`. Rules: no single module dominates, conflicting recommendations must be shown honestly, unknowns stay Unknown, never fabricate consensus, never hide disagreement. Mission Control must display Council Recommendation/Confidence/Supporting Evidence/Disagreements/Risks/Expected Impact/Long-term Effect. Learning: every final Founder decision becomes institutional knowledge — compare Recommendation vs Founder Decision vs Real Outcome, then improve future recommendations. Constitution-first, ethics preserved, Founder approval required for irreversible strategic decisions (unchanged, not loosened).

## The one finding that reframed this build

A research audit (this session's own, file:line verified) found that `executive_board.py` (Executive Directive, 2026-07-22) already solves this exact class of problem once, under different member names: 10 C-suite roles (CEO/CTO/CFO/COO/CPO/Chief Market Intelligence/Chief Risk/Chief Revenue/Chief Customer/Chief Innovation Officer), each already returning `{role, recommendation, risks, opportunities, missing_evidence, confidence, vote}` — a near-1:1 precursor of this directive's 6 required fields. Its own docstring already states "no single agent may approve strategic decisions alone," enforced structurally (`convene_board()` is the only function that produces a board decision). `_tally()` already counts APPROVE/REJECT/DEFER (majority for production decisions, unanimity for irreversible ones) and surfaces unresolved DEFER votes explicitly. Every convening is permanently recorded (`data/board_meetings.jsonl`). `review_board_track_record()` already implements a real 2-way learning loop (past board decision vs. real market evidence accumulated since, `matched: True/False/None` — `None` meaning honestly "too soon to tell").

There is also a third, pre-existing, separate roster: `OpenClaw_Brain/06_Councils/README.md` maps `CONSTITUTION.md`'s 12 named "Councils" (Quality, Golden Hunter, Engineering, Knowledge, Security, Digital Sanitation, Executive, Innovation, Publishing, Marketing, Investment, Product Lifecycle) to real code.

**None of these three rosters (Constitution's 12 / Executive Board's 10 C-suite roles / this directive's 10 Galaxy Council names) share membership — this is not a rename.** But the *mechanics* (honest disagreement, non-fabricated consensus, permanent recording, decision-vs-outcome learning) were already solved and battle-tested. **Decision: `galaxy_council.py` reuses `executive_board.py`'s tally/consensus/disagreement/track-record-review pattern as its literal template, rather than re-solving the same problem from scratch.** The Council answers a genuinely different question than the Board: "what does each intelligence domain currently believe about this niche, laid out honestly side by side" (Council) vs. "should we approve this one already-evaluated decision" (Board). Both stay — deliberately distinct bodies. A one-line cross-reference was added to `OpenClaw_Brain/06_Councils/README.md` to prevent future confusion between all three rosters.

## What was built

**`galaxy_council.py` (new)** — 9 real member-normalizer functions (the directive's 10th named member, Mission Control, is the display venue for the other 9, not an analytical producer — deliberately not given a fabricated 10th opinion; this is a disclosed scope decision, not a silent omission). Every member is a pure citation of an already-real signal, mirroring `resilience_monitor.py`'s per-signal `_classify_*()` functions and `strategic_intelligence_core.py`'s `_extract_signal()` citation-layer discipline:

| Member | Real source | Scope |
|---|---|---|
| Strategic Intelligence Core | `strategic_intelligence_core.strategic_score(niche)` | niche |
| Market Intelligence | `competitor_discovery`'s real **cached** snapshot (never a live network call, same discipline as `ceo_decision_center.py`'s `_market_saturation_and_strength()`) + `market_alerts.get_active_alerts()` | niche |
| Production Intelligence | new `_latest_inspection_for_niche()` (a tiny reader over `inspectors.py`'s real `inspections.log`, never a new inspection engine) + `executive_intelligence.engine_health.compute_engine_health()` | niche + company-wide context |
| Customer Intelligence | `customer_pipeline`'s 3 real Observe signals | company-wide only — no niche field exists in this factory's real customer request schema |
| Financial Intelligence | `profit_oracle.opportunity_score(niche)` + `channels.ledger.revenue_trend()` | niche + company-wide context |
| Security Intelligence | `executive_quality_gate`'s Global Policy Engine checks (both honestly UNKNOWN-by-design) + `ai_doctor`'s real dependency-pinning drift | company-wide only |
| Resilience Intelligence | `resilience_monitor.assess_resilience()` | company-wide only |
| Innovation Intelligence | `evolution_engine.build_evolution_report()` + `tool_intelligence.proposals.list_proposals()` | company-wide only |
| Executive Memory | `decision_engine.store.find_decisions_by_niche()` (citing `alternatives_rejected`/`expected_outcome`, Decision Memory) + any matched real `Outcome` | niche (per decision_id) |

Customer/Security/Resilience/Innovation are structurally company-wide-only today (confirmed by direct search: no niche field exists anywhere in their real underlying data models) — `convene_council()` calls them every time regardless, tagged `scope: "company_wide"`, never silently skipped and never forced to fabricate a per-niche answer they don't have.

**Disagreement algorithm.** The 9 members are not on one comparable scale — forcing them onto a synthetic agree/disagree axis would itself be a fabricated consensus. Each member tags a `stance` (`proceed`/`hold`/`stop`/`no_data`/`informational_context`) only where its own real source already emits something genuinely comparable to a go/no-go signal (Financial's `accepted` boolean, Production's `passed` boolean, Market's critical/high alert presence, Strategic's `at_risk` flag); members whose real sources are informational-only by their own existing docstrings (Security/Resilience/Innovation/Customer) are tagged `informational_context` and never coerced onto the axis. `disagreement_detected` is true iff 2+ members with a real stance genuinely disagree — generalizing `decision_engine.engine`'s real 2-signal-must-agree rule to N members. When members agree, `council_recommendation`/`council_confidence` are a real citation of that agreement (mean confidence, same `_aggregate_confidence()` precedent as `executive_board.py`); when they disagree, both are honestly `"SPLIT — see disagreeing_members"` — never a blended fake verdict. `expected_impact`/`long_term_effect` (the directive's own named display fields) cite Strategic Intelligence Core's own already-real `strategic_value`/`long_term_value` dimensions via an additive `raw` field on its member result — never a second call to `strategic_score()`.

**Learning substrate.** `data/council_recommendations.jsonl` (new, append-only, same convention as `data/board_meetings.jsonl`/`data/incidents.jsonl`) records what the Council actually recommended AT THE TIME it was convened — the real missing first leg no prior module persisted (only the eventual Decision + Outcome existed, a 2-way link). `record_council_recommendation()` is an explicit, human/caller-invoked append — never automatic (this factory has no scheduler). `council_learning_summary()` does a real, mechanical 3-way join (Council Recommendation → the real Founder Decision that followed, from `decision_engine.store` → the real eventual Outcome, from the same store) with the same `matched`/`diverged`/`pending`/`too_soon_to_tell` non-forced-verdict discipline as `executive_board.review_board_track_record()`. A `SPLIT` council session honestly reports `no_clear_council_position` rather than a forced match/diverge. Honestly `"NOT ENOUGH EVIDENCE"` — this factory starts at zero real recommendation→decision→outcome triples today, never backfilled for the 1360+ real pre-existing decisions or 1 real board meeting that predate the Council's existence.

**Mission Control.** `mission_control_api.py` gained `convene_galaxy_council`/`record_council_recommendation`/`council_learning_summary` endpoints. `server.js`'s `ACTION_REGISTRY` gained `convene-galaxy-council`/`record-council-recommendation` (the correct precedent to copy — `convene-executive-board`'s async-job shape with a 15-minute timeout, not the company-wide `SERVICE_REGISTRY` 30-second-default shape, since a per-niche convening chains several real sub-calls). A `galaxy-council-learning` `SERVICE_REGISTRY` entry (cheap, no-input, same underlying python section as the action) feeds a new no-input `kv` panel in `mission_control_executive_v1.html`. The niche-scoped convening got a real button (`🏛️ استدعِ مجلس المجرة`) in `mission_control.html`'s Opportunities tab, reusing that file's existing niche-input precedent (`go-deep-evidence`'s prompt-driven modal flow) rather than inventing a new UI pattern.

## Constitution-first / no-autonomous-high-risk boundary (deliberately unchanged)

Every function in `galaxy_council.py` is read-only and recommend-only. `convene_council()` persists nothing by itself; only the explicit, human-triggered `record_council_recommendation()` writes anything, and it only ever appends. Nothing here spends money, publishes anything, deletes data, or changes any legal/payment/strategy setting. Constitution-first (`executive_quality_gate.check_constitution_alignment()`, cited directly by the Security Intelligence member) and no-autonomous-high-risk-decisions (`evolution_queue.py`, `channels/publish_protection.py`, `safe_mode.py`, all already human-gated for anything irreversible) were both already real and already applied everywhere a real decision is made in this factory before this round began — this ADR cites that fact rather than re-implementing it.

## Validation

New tests: `tests/test_galaxy_council.py` (new, 39 — every member's real-signal and honest-Unknown/no_data paths, `convene_council()`'s disagreement detection including the never-average-away-disagreement guarantee, the append-only learning substrate, and the 3-way join's `matched`/`diverged`/`pending`/`no_clear_council_position` paths, every real source mocked), `tests/test_mission_control_api.py` (+5, the new dispatch endpoints).

Live E2E against real factory data: `convene_council()` run directly against a real ACCEPTED niche ("workflow automation system for logistics companies") produced a genuine, real disagreement — Production Intelligence said `stop` (a real failed Dual Inspection commercial audit for this exact niche) while Financial Intelligence said `hold` (a real below-threshold `opportunity_score`) — and `disagreement_detected` correctly triggered, `council_recommendation` honestly reported `"SPLIT"`, never blended into a fake single verdict. `expected_impact`/`long_term_effect` correctly cited Strategic Intelligence Core's own real `strategic_value: 47.0`/`long_term_value` dimensions without a second `strategic_score()` call (confirmed via a mock-assert-not-called test). The append-only learning substrate was confirmed genuinely append-only across two real convenings of the same niche. `council_learning_summary()` was confirmed to report the honest `NOT ENOUGH EVIDENCE` state on a fresh, zero-recommendation ledger. The full `convene-galaxy-council` action was verified live end-to-end through a real, logged-in `server.js` HTTP round-trip (POST → async job → poll → `completed` with the real session result) — the exact discipline that caught a real timeout bug in the previous round (Strategic Intelligence Core), applied again here before declaring the wiring done.

A real, pre-existing environment quirk was found (not a code defect): this machine's `python3` alias (Windows `WindowsApps` App Execution Alias) adds a fixed ~30-second startup tax per invocation compared to the `python` alias, which `detectPython()` does not distinguish between (it tries `python3` first). This does not break anything — `PYTHON_ACTION_TIMEOUT_MS` is 15 minutes — but explains why a live action-triggered convening took ~30s versus a few seconds when invoked directly via `python mission_control_api.py ...` in this session's own verification. Not fixed as part of this round (out of scope — a pre-existing, harmless-today environment characteristic, not a Galaxy Council defect); noted here for whoever investigates action-latency reports in the future.

## What's still honestly Unknown / not built

`council_learning_summary()` will report `NOT ENOUGH EVIDENCE` for a long time by design — it requires a real founder to actually call `record-council-recommendation` for real niches going forward, and then real decisions/outcomes to accumulate after that; this ADR is the record of that being the honest, correct behavior for a freshly-built module, not a gap to "finish later." Security Intelligence's `founder_approval_required` stays `False` unconditionally today — a live-publish-imminent ToS-awareness escalation was considered but deliberately deferred as a real, narrow follow-up (would need to thread real target-platform context into `convene_council()`, out of this round's scope). Four unrelated, unexplained orphaned `node server.js` processes were found on this machine during live verification (not spawned by this round's own work, not bound to any port) — flagged to the founder directly rather than force-killed, per this factory's standing "never blindly `taskkill` node.exe" policy.
