# ADR-139 — Capital Allocation Engine

**Date:** 2026-07-29
**Status:** Adopted.

---

## The directive

"EXECUTIVE DIRECTIVE — CAPITAL ALLOCATION ENGINE": Galaxy Forge must continuously decide where every hour, dollar, AI token, infrastructure resource, and human effort is invested. Every initiative gets a continuously updated 14-dimension "Investment Score" (Expected Revenue, Recurring Revenue Potential, Customer Impact, Strategic Importance, Market Defensibility, Competition Level, Automation Potential, Engineering Cost, Maintenance Cost, Risk, Execution Complexity, Knowledge Reuse, Brand Value, Long-Term Asset Value). Dynamic resource recommendations (Increase/Maintain/Reduce/Pause/Terminate/Accelerate immediately/Research before investing). Never continue investing simply because past work exists — future value only. Detect opportunity cost (name the higher-value initiative being delayed). Mission Control exposes a Capital Allocation Dashboard: Top ROI Initiatives, Projects Losing Value, Projects Consuming Resources Without Results, Resource Distribution, Expected Portfolio Return. Protect against shiny-object syndrome, over-expansion, emotional investment, founder bias, sunk-cost fallacy. Founder remains final authority — the engine recommends, never executes.

## The one finding that reframed this build

A research audit (this session's own, file:line verified) found **7 of the directive's 14 named dimensions directly duplicate `strategic_intelligence_core.py::strategic_score()`'s existing 11 named dimensions** — built in the immediately preceding round of this same session: Recurring Revenue Potential≈`recurring_revenue`, Competition Level≈`competition`, Automation Potential≈`automation`, Risk≈`risk`, Strategic Importance≈`strategic_value`, Long-Term Asset Value≈`long_term_value`, Execution Complexity≈`difficulty`. Building a second, parallel `investment_score()` citation function from scratch would have silently duplicated architecture one round after this factory's own "never build a second, competing citation layer" lesson (the exact bug found and fixed in `strategic_score()` itself last round — a redundant `scheduler.decide_next_actions()` call). **Decision: `capital_allocation_engine.py::investment_score(niche)` delegates verbatim to `strategic_score(niche)` for the 7 overlapping dimensions, and adds new citations only for the genuinely distinct 7** (Expected Revenue, Customer Impact, Market Defensibility, Engineering Cost, Maintenance Cost, Knowledge Reuse, Brand Value).

Of those 7 new dimensions, 3 turned out to already be honestly disclosed as `Unknown` *inside `value_engine.py` itself* (`_NO_REAL_SOURCE_DIMENSIONS`, lines 64-68): `expected_customer_value` (Customer Impact), `brand_building_impact` (Brand Value), and — via `board_summary.estimated_lifetime_value`'s own real-sale-only gate — the closest honest proxy for Expected Revenue. `Maintenance Cost` (`board_summary.estimated_maintenance_cost`) is *also* always `Unknown` today by the same module's own disclosure ("no real post-launch maintenance-cost tracking system exists yet"). No new code was needed for any of these four — only honest citation.

## What was built

**`capital_allocation_engine.py::investment_score(niche)`** — the 14-dimension citation layer described above. `_engineering_cost_citation()` and `_knowledge_reuse_citation()` are the two dimensions with real shapes distinct enough from `strategic_score()`'s own `_extract_signal()` normalizer that they needed a dedicated, small citation function each — `Engineering Cost` cites `board_summary.estimated_build_cost`'s own `{"maturity": "REAL"/"DISCOVERY", ...}` shape (`revenue_pipeline.plan.estimate_production_cost()`'s real average logged Groq cost); `Knowledge Reuse` is a real textual synthesis of 3 already-real dimensions (`knowledge_accumulation`, `synergy_with_existing_products`, `bundle_potential`) — `knowledge_accumulation`'s own real `level` is the headline value, the other two folded into the reason only when themselves real (never Unknown).

**`opportunity_cost()`** — the directive's real, narrow gap: no existing signal anywhere in this factory named "which higher-value initiative is a given resource allocation delaying." Built as a real, evidence-based pairing: for every real ACCEPTED opportunity in `scheduler.py`'s own `wait`/`stop`/`cancel` buckets, cites which `run_now`/`accelerate` bucket member(s) rank higher by the exact same real Priority Score order `value_engine.build_value_engine_report()` already computed — never a fabricated claim, never a new ranking. Accepts optional `portfolio`/`scheduling` injection (mirroring `scheduler.decide_next_actions()`'s own `portfolio` param) so `build_capital_allocation_dashboard()` below never triggers the real ~10-25s full-portfolio scan a second time.

**`stuck_without_production()`** — "Projects Consuming Resources Without Results": a real ACCEPTED decision with zero real production attempt ever logged (`value_engine.classify_lifecycle_stage()`'s own real `prototype` stage, citing `production_evidence.record.build_evidence_record()` verbatim) across a real, disclosed elapsed-time threshold (default 7 days) since it was decided. Modeled on `customer_pipeline.py`'s existing stuck-request detection pattern (stage-based staleness, already cited in `tool_intelligence/proposals.py`) — never a new judgment engine.

**`build_capital_allocation_dashboard()`** — the one real aggregator: `top_roi_initiatives` (top 10 by real Priority Score, from `build_value_engine_report()`), `projects_losing_value` (real `at_risk`-flagged opportunities across the portfolio — a governance-risk signal, disclosed as such, never a fabricated financial-loss claim), `projects_consuming_resources_without_results` (cites `stuck_without_production()`), `resource_distribution` (cites `scheduler.decide_next_actions()`'s real bucket counts + `ceo_decision_center.capital_allocation_snapshot()`'s real 10 named department attention counts — a different, already-real thing, cited as company-wide context, not rebuilt), `expected_portfolio_return` (a transparent average of only the portfolio's real, non-Unknown `roi_pct` values, disclosing how many were excluded — same precedent as `executive_score.py`/`resilience_monitor.py`'s own transparent averages), `opportunity_cost_summary` (cites `opportunity_cost()`). The real portfolio+scheduling scan is computed exactly once and threaded through every field that needs it.

**Sunk-cost/shiny-object/founder-bias protection** — documentation, not code. Confirmed by direct signature inspection: neither `profit_oracle.opportunity_score()` nor `value_engine.compute_value_profile()` accepts any cumulative-past-spend parameter anywhere in their real parameter lists. A decision here is architecturally incapable of being anchored to money already spent — every real score is re-derived fresh from current evidence each call. This is recorded here as a disclosed, deliberate structural property, not a gap to "finish later" with a new sunk-cost-detection algorithm (which would itself require tracking cumulative spend, i.e., building the very anchor this factory has always avoided).

**Mission Control.** `mission_control_api.py` gained `investment_score`/`opportunity_cost_report`/`capital_allocation_dashboard` endpoints. `server.js`'s `SERVICE_REGISTRY` gained `capital-allocation-dashboard` — measured live at ~22-25s of real compute, given a disclosed 90-second timeout (the same real-outlier class as `executive-brief`, for the same reason: it chains `build_value_engine_report()` + `decide_next_actions()`, each independently non-trivial). `ACTION_REGISTRY` gained `investment-score` (niche-scoped, 15-minute async-job timeout, same `convene-galaxy-council` precedent). `mission_control_executive_v1.html` gained a no-input `capital-allocation-dashboard` panel; `mission_control.html`'s Opportunities tab gained a "💰 Investment Score" button reusing the exact niche-input modal/renderer pattern built for Galaxy Council last round.

## Recommendation-category gap (disclosed, not invented)

`scheduler.py::decide_next_actions()`'s real `accelerate`/`stop`/`cancel`/`run_now`/`wait` buckets map onto 5 of the directive's 7 named categories (Increase→`accelerate`, Terminate→`cancel`, Maintain→`run_now`/`wait`, Pause→`stop`; "Research before investing" maps to `decision_engine`'s real `RESEARCH_REQUIRED`/`DEFERRED` statuses). **No real, distinct signal exists today for "Reduce" as separate from "Pause,"** nor for "Accelerate immediately" as separate from plain "Increase" — `scheduler.py` has one flat `accelerate` bucket and one flat `stop` bucket. This module does not invent that finer granularity; it cites the real 5-bucket system honestly, disclosing the gap here rather than fabricating two new categories with no real evidence behind them.

## Constitution-first / no-autonomous-high-risk boundary (deliberately unchanged)

Every function in `capital_allocation_engine.py` is read-only and recommend-only. Nothing here spends money, reallocates a real budget, or changes any legal/payment/strategy setting — this factory has no live worker pool or payroll to actually reallocate in the first place (the same honest disclosure `ceo_decision_center.capital_allocation_snapshot()`'s own docstring already makes). The Founder remains the sole real authority on every reallocation decision this module's output might inform.

## Validation

New tests: `tests/test_capital_allocation_engine.py` (new, 22 — `investment_score()`'s 7 delegated + 7 new dimensions including the no-real-profile honest-Unknown path, `_knowledge_reuse_citation()`/`_engineering_cost_citation()`'s real-shape handling, `opportunity_cost()`'s pairing logic including the never-recompute-the-portfolio guarantee and the never-pair-a-niche-with-no-real-rank guarantee, `stuck_without_production()`'s age/production-attempt gating, `build_capital_allocation_dashboard()`'s field-by-field citation including the transparent-average-excludes-Unknown-values guarantee, every real source mocked), `tests/test_mission_control_api.py` (+4, the new dispatch endpoints).

Live E2E against real factory data: `investment_score()` run against a real ACCEPTED niche ("workflow automation system for logistics companies") correctly resolved a mix of real values (competition=70, engineering_cost=$0.0001 real average over 139 real Groq calls) and honest Unknowns (customer_impact, market_defensibility, brand_value, expected_revenue) exactly where the underlying real sources have no signal for this niche yet. `build_capital_allocation_dashboard()` run directly against real factory data (3 real ACCEPTED opportunities) took ~22s and correctly surfaced a real `projects_losing_value` entry (a real board-rejected niche), 2 real `projects_consuming_resources_without_results` entries (both ACCEPTED 7.5 real days ago with no real orchestrator-tracked production attempt), and 2 real `opportunity_cost` pairings. A real, pre-existing data quirk was found and disclosed, not fixed (out of this round's scope, belongs to `revenue_pipeline/plan.py::estimate_roi()`): when a real logged production cost is near-zero (this factory's real average Groq cost is $0.0001/call), the real ROI-percentage formula produces an arithmetically-correct but visually absurd number (hundreds of millions of percent) — `expected_portfolio_return`/`top_roi_initiatives` cite this verbatim, since fabricating a capped or "corrected" number would itself be dishonest. Full regression: Python + Node suites both clean except one confirmed-unrelated pre-existing failure (see below). The full `capital-allocation-dashboard` service and `investment-score` action were both verified live through a real, logged-in `server.js` HTTP round-trip before declaring the wiring done.

## What's still honestly Unknown / not built

`Customer Impact`, `Market Defensibility` (for any niche with no cached competitor scan), `Brand Value`, and `Expected Revenue` (for any niche with no real closed sale yet) will report `Unknown` for the overwhelming majority of this factory's real opportunities for the foreseeable future — this ADR is the record of that being the honest, correct output for a factory with no NPS system, no brand-metric connector, and mostly pre-sale opportunities, not a gap to "finish later" by inventing a proxy. The "Reduce"/"Accelerate immediately" recommendation-category gap (above) stays open until a real, distinct signal for graduated resource reduction actually exists somewhere in this factory. `estimate_roi()`'s near-zero-cost percentage-blowup quirk (above) is flagged for a future, separately-scoped fix — this round only cites it, never patches the underlying formula.
