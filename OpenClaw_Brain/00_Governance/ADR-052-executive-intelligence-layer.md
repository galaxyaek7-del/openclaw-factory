# ADR-052 — Executive Intelligence Layer: تقرير تنفيذي يومي، صفر رقم مُختلَق

**التاريخ:** 2026-07-16
**الحالة:** مُنفَّذ ومُختبَر بالكامل (248 اختباراً بايثون + 69 جافاسكريبت، كلها تمر).
**يُنفِّذ:** توجيه الرئيس — "Do not add new engines. Build the Executive Intelligence Layer on top of the existing infrastructure."

---

## القرار

حزمة `executive_intelligence/` جديدة — **طبقة قراءة فقط بلا كتابة، بلا محرّك جديد في سجلّ `orchestrator`**، تُجمِّع كل الإشارات الحقيقية الموجودة فعلاً في: `data/orchestrator_timeline.jsonl` (`ADR-051`)، `data/decisions.jsonl`/`data/decision_outcomes.jsonl` (`ADR-050`)، `channels/registry.py`/`data/sales_ledger.jsonl` (موجودة مسبقاً هذه الجلسة).

```
executive_intelligence/
  engine_health.py       — صحة كل محرّك من السجل الزمني الفعلي فقط
  opportunities.py         — تتبُّع كل قرار (مقبول/مرفوض/مؤجَّل) + سببه الحقيقي المُخزَّن
  bottlenecks.py             — اكتشاف اختناقات حقيقية (نسبة فشل محرّك، تقادم طابور القرار)
  revenue_distance.py          — عوائق حقيقية نحو أول إيراد، لا تقدير زمني رقمي مُختلَق
  inactivity.py                  — مكوّنات صفر نشاط (محرّكات/أذرع نشر)
  report.py                       — التجميع + عرض Markdown للرئيس التنفيذي (<60 ثانية قراءة)
```

## الانضباط الحاكم: لا رقم بلا مصدر حقيقي، صدق بدل التقدير

كل قسم يُصنَّف صراحة **REAL** (بيانات حقيقية موجودة فعلاً) أو **DISCOVERY** (غير محسوبة بعد، مع السبب) — لا حالة وسطى مُلمَّعة. أمثلة ملموسة تحقَّقت فعلياً بتشغيل التقرير على البيانات الحقيقية اليوم (صفر تشغيل حقيقي لـ`orchestrator`/`decision_engine` بعد):

- **صحة المحرّكات:** كل الخمسة (`market_intelligence`, `decision`, `production`, `publishing`, `learning`) تُقرَأ `DISCOVERY` — "لا تنفيذ واحد مسجَّل بعد" — **صحيح فعلياً**، لا افتراض "سليم" افتراضي.
- **دقة التنبؤ:** `accuracy: None` — "لا قرارات ACCEPTED بعد لقياسها" — بدل نسبة مُختلَقة.
- **المسافة نحو أول إيراد حقيقي:** **لا تقدير زمني رقمي إطلاقاً** — بدلاً منه عائقان حقيقيان محدَّدان: (1) صفر ذراع نشر بحالة `READY` (`channels/registry.py`) — لا مفتاح API حي بعد، (2) صفر فرصة `ACCEPTED` في طابور القرار. هذا التصميم مقصود: **لا سجل مبيعات حقيقي واحد موجود لبناء معدَّل تنبؤ عليه** — أي رقم زمني كان سيكون اختلاقاً صريحاً، بالضبط ما يمنعه هذا الـADR.

## اكتشاف الاختناقات — إشارتان حقيقيتان فقط، لا استدلال إضافي

1. محرّك بنسبة نجاح حقيقية أقل من 80% (يحتاج تنفيذاً حقيقياً واحداً على الأقل ناجحاً وفاشلاً ليُحسَب، وإلا `DISCOVERY` من `engine_health.py`).
2. فرصة `ACCEPTED` جالسة في طابور القرار (`decision_engine.ranking.rank_queue()`، مُعاد استخدامه لا مُعاد بناؤه) لـ3 أيام حقيقية أو أكثر بلا تنفيذ إنتاج/نشر.

بلا أي منهما: **"لا اختناقات حقيقية مكتشَفة"** صراحةً — لا اختلاق اختناق لجعل التقرير يبدو أعمق تحليلاً مما تسمح به البيانات.

## أعلى فرصة بانتظار التنفيذ + شرح كل قرار

كلاهما إعادة استخدام مباشرة لبيانات مُخزَّنة فعلاً: `decision_engine.ranking.rank_queue()`'s أول عنصر (لا ترتيب جديد)، و`Decision.reasoning` (`ADR-050`) — القائمة النصية الحقيقية المُخزَّنة وقت اتخاذ كل قرار، مُعادة كما هي، لا مُلخَّصة أو مُعاد صياغتها.

## صفر محرّك جديد

`executive_intelligence/` **لا يستورد `orchestrator.registry`، ولا يُسجِّل شيئاً فيه.** كل قراءاته عبر الوحدات الموجودة مسبقاً مباشرة (`orchestrator.timeline`, `decision_engine.store`/`ranking`/`learning`, `channels.registry`/`ledger`) — طبقة تجميع فوقية بحتة، تماماً كما طُلِب.

## الأثر

- ملفات جديدة: 7 تحت `executive_intelligence/` + هذا الـADR.
- `tests/test_executive_intelligence.py`: 16 اختباراً جديداً (المجموع الآن 248 بايثون).

- أداة مستقلة تُشغَّل عمداً (`python -m executive_intelligence.report`) — لا ربط تلقائي، نفس اتفاقية كل أداة جديدة هذه الجلسة.
