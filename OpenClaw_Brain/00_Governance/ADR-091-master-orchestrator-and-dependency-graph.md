## 1. Factory Master Orchestrator (`factory_orchestrator.py`)

The single real call composing `executive_quality_gate.py` (ADR-087) → `executive_board.py` (ADR-090, which itself calls `enterprise_readiness.py`, ADR-089) → `revenue_pipeline.pipeline.process_opportunity()`, instead of 3+ separate manual Mission Control actions. Wraps, never rewrites, every stage.

- `advisory_only=True` by default (an explicit design decision baked into the module's own docstring, not something this audit chose): the Board's verdict is reported alongside a real `execute=True` production run but does not block it. Hard-gating on the Board today would freeze all production, since zero real market evidence exists for any niche yet — the same freeze risk the prior audit flagged. `enforce_board=true` makes a real `NOT_APPROVED` tally actually block production.
- Reachable via `POST` to the Mission Control action `run-master-cycle` (`server.js`) → `run_master_cycle` (`mission_control_api.py`).
- **Verified today:** the 7 pre-written unit tests pass (`python -m unittest tests.test_factory_orchestrator -v`). Beyond that, this audit ran it live against a real `ACCEPTED` decision (`"workflow automation system for logistics companies"`, one of 3 real `ACCEPTED` decisions in `data/decisions.jsonl` today) with `execute=False`. It returned a real Quality Gate result (honest `UNKNOWN` on customer-pain/WTP/competitor evidence — none exists yet — real `PASS` on technical feasibility, legal risk, delivery capability, scalability) and a real 10-vote Board tally (4 APPROVE / 4 REJECT / 2 DEFER → `NOT_APPROVED`). No fabricated field anywhere in the output.
- **Side-effect found and cleaned up:** this live verification call wrote two real records to `data/board_meetings.jsonl` (the module's real default write path). Since these were audit verification runs, not real business decisions, the file was deleted after inspection rather than left as an artifact misrepresenting real governance activity — anyone rerunning `run_master_cycle` for a real decision will recreate this file legitimately.

## 2. Dependency Graph (`dependency_graph.py`) — real bugs found and fixed today

Builds a real module dependency graph from actual `import` statements via the standard-library `ast` module (185 internal modules, first-party only). Three real defects were found by running the tool against this actual repo and manually verifying its output against the real source — not assumed, not guessed:

1. **Submodule truncation.** `from decision_engine import ranking` was recorded as a dependency on `decision_engine` only (`.split(".")[0]`) — `decision_engine.ranking`, a real file `factory_orchestrator.py` itself imports, never appeared as an import target anywhere. This alone made ~100 real, actively-used submodules look like zero-dependent orphans. **Fixed:** `_resolve_imports()` now checks both the package and, if it's a real file, the specific submodule.
2. **Relative imports silently skipped.** `from . import etsy_publisher` (`channels/etsy_arm.py`) was dropped entirely on the documented-but-wrong assumption that relative imports "aren't resolved by name here" — they are: PEP 328's own resolution rule (walk up `level` package segments from the importing file's own package) is fully computable from `ast.ImportFrom.level` plus the importing file's path. **Fixed:** `_resolve_relative_base()` implements this; verified against `channels/etsy_publisher.py`, `gumroad_publisher.py`, `payhip_publisher.py` no longer appearing as false orphans.
3. **Deferred imports counted as cycle-time edges.** `dossier_bundle/build_bundle.py` contains an explicit, commented, deliberate function-body import specifically to break a real circular dependency with `production_factory/dossier.py`. Because the original cycle detector walked the *entire* AST (including function bodies) without distinguishing them from module-level imports, it reported this already-solved cycle as a live defect. **Fixed:** cycle detection now runs against a module-level-only graph (`_ModuleLevelImportCollector`, which does not descend into `FunctionDef`/`AsyncFunctionDef` bodies); the full graph (including deferred imports) is kept for `dependents_of()`/orphan detection, where a deferred import is still a real change-impact dependency, just not an import-time one.
4. **Ancestor packages not counted (found during the fix above, not separately reported as a "bug" since it was never claimed to work — a real gap closed, not a regression).** `from dossier_bundle.build_bundle import x` always executes `dossier_bundle/__init__.py` first (real Python import semantics), so `dossier_bundle` itself has a real dependent even though no code imports it by that exact name. Added `_with_ancestor_packages()`.

**Verified empirically, not just via the tool's own output:** the one remaining "cycle" the fixed detector found (`product_families` ↔ `asset_generation` via `pdf_builder.py`'s `from product_families.spec import ...`) was checked by actually running `python -c "import product_families"` and `python -c "import asset_generation.builders.pdf_builder"` — both succeed with no `ImportError` today. The tool's docstring now carries this caveat explicitly: a reported cycle means "worth a human look," never "confirmed broken," because `sys.modules` pre-registration makes many package-level submodule cycles safe in real Python even though the graph is genuinely cyclic.

**Known, honest, undismissed limitation, not silently worked around:** `market_intelligence_core/scoring/`, `multi_source_intelligence/connectors/`, and `orchestrator/engines/` all use `pkgutil.iter_modules` + `importlib.import_module` for plugin auto-discovery (each package's own `__init__.py` says so). A static AST-based tool fundamentally cannot see a dynamically-constructed module name — these ~24 submodules still show as "zero-dependent candidates" in this tool's output and are **not** orphans; this is disclosed here and in the tool's own `find_zero_dependent_modules()` docstring rather than papered over with a hardcoded exclusion list that would silently go stale.

- **New test coverage:** `tests/test_dependency_graph.py`, 8 tests, all passing, built against small real throwaway package trees (never mocks the parser itself) — one test per fix above, plus the ancestor-package addition.

## 3. Real bug found by chance during verification: `market_hunter.hunt_market()` had no test-isolation path for its decision-recording side effect

Live-verifying `run_master_cycle` (§1) meant booting the server and running the full test suite multiple times. Diffing `git status` before and after each run surfaced `data/decisions.jsonl` — the single real source of truth every decision surface reads (ADR-076) — changing on every test run, which it must never do.

**Root cause:** `hunt_market()` (line 316, pre-fix) called `RECORD_LADDER_DECISION(niche, ladder, scored)` unconditionally, with no way to redirect the write. `decision_engine.engine.record_ladder_decision()` already accepts a `decisions_path=None` override — the exact mechanism `factory_orchestrator.py`, `revenue_pipeline`, and nearly every other stateful module in this factory already uses for test isolation — `hunt_market()` alone never threaded it through. `tests/test_market_hunter_sensing_link.py`'s 4 real `hunt_market()` calls had no isolation switch to use, so every run of that file (and this factory's own full test suite, transitively) wrote real ladder-decision records for fixture niches (`"what is a monsoon"`, `"a real pioneer test candidate niche xyz"`) into the live governance ledger.

**Scale, checked before fixing anything:** `git show HEAD:data/decisions.jsonl | grep -c` these two fixture niches = **174 lines already committed** from prior sessions' test runs, before this audit touched anything. This session's own verification runs (full suite executed multiple times) added **86 more** (260 total) before the fix landed.

**Fix:**
1. `market_hunter.py`: `hunt_market(limit=10, write_opportunities=True, decisions_path=None)`, threaded into the `RECORD_LADDER_DECISION(..., decisions_path=decisions_path)` call.
2. `tests/test_market_hunter_sensing_link.py`: every real `hunt_market()` call now passes a `tempfile`-backed `decisions_path`, cleaned up in `tearDown`; added `test_real_decisions_are_written_to_the_given_path_not_the_live_ledger` to lock this in.
3. **A real regression caught before it shipped, not after:** `tests/test_market_hunter_decision_recording.py` and `tests/test_unified_pipeline_e2e.py` already patched `RECORD_LADDER_DECISION` with hand-written replacement functions of fixed 3-argument signatures (`niche, ladder, scored`). Adding the `decisions_path=` keyword to every call site meant those patched replacements would now raise `TypeError` on every call — silently swallowed by `hunt_market()`'s own `except Exception: pass` around that call, which would have made both tests fail with no write ever happening, and no obviously-related error message. Running each test file individually caught this immediately; both replacement signatures were updated to accept `decisions_path=None`. All 18 tests across the 3 affected files pass; the live ledger was diffed byte-for-byte before and after each run to confirm zero further writes.
4. **Ledger cleanup, not left as a known issue:** the 260 accumulated fixture-niche lines were removed from `data/decisions.jsonl` by exact niche-name match (never touching any other line, never re-serializing surviving lines — original text preserved byte-for-byte). Verified after: all 1356 remaining lines parse as valid JSON, and `decision_engine.ranking.rank_all()` still returns the same 3 real `ACCEPTED` decisions that existed before cleanup (`workflow automation system for logistics companies`, `inventory management system for wholesale distributors`, `automated invoice processing toolkit for small businesses`) — the fix removed only synthetic test data, never real business history.

This is disclosed as what it is: a real, multi-session data-integrity bug in a governance ledger this factory treats as its single source of truth, found by accident while verifying something else, not something this audit went looking for.

## 4. Full regression evidence

`python -m unittest discover -s tests -p "test_*.py"`: **1038 tests, 0 failures** in the final run (after the `market_hunter.py` fix above; 1037 immediately prior, +1 net from the new `test_market_hunter_sensing_link.py` test) — not sampled, not skipped, not assumed. `data/decisions.jsonl` and `data/ai_cost_log.jsonl` were diffed before and after this final run: the decisions ledger did not change at all; the cost log gained exactly one entry, from `tests/test_product_package.py`'s own explicitly-documented single deliberate real Groq call (can't mock across a subprocess boundary — the one real-integration proof for the techdoc content path, at ~$0.0001). `node --check server.js` passes; the server was booted live on a scratch port (`PORT=3199`) and `GET /api/dashboard` returned `200`.
