# ADR-083 — Strategic Phase 3, Round 1

**Date:** 2026-07-22
**Status:** Adopted. Round 1 of a multi-round rollout — Round 2/3 remain a documented roadmap, not built this round.

---

## Why this exists

`STRATEGIC_PHASE_3.md` records the founder's mission reframe and 5 named priorities (Opportunity Intelligence Engine, Golden Hunter Evolution, Product Laboratory, Market Validation, Continuous Evolution). This ADR is the build record: what three parallel research passes found already real (don't rebuild), and what was actually built this round.

Two safety constraints, confirmed by research and preserved throughout: (1) every existing live-network research module (`competitor_discovery.py`, `multi_source_intelligence/`) was deliberately kept out of `profit_oracle.py`'s synchronous scoring / the automatic daily tick, to avoid unbounded live-network cost on autopilot — this round's Track A items respect that boundary rather than crossing it; (2) `ADR-039`'s discipline (founder's own words: "never create fake metrics") governs every new scoring field — real data or honestly `Unknown`, never a fabricated number.

## What research found already real (no new work)

- **Opportunity Intelligence Engine**: `multi_source_intelligence/` (`ADR-059`) already covers almost the founder's exact named source list — real for Hacker News/GitHub/Stack Overflow, honestly blocked for Reddit ($12,000/mo hard financial wall), Product Hunt (needs prior business contact per ToS), Google Trends (needs n8n activation). `competitor_discovery.py` (`ADR-042`) already does real HN+GitHub competitor discovery with 5-category classification and a 7-day cache.
- **Golden Hunter Evolution's 9 dimensions**: mapped precisely against real code — competition, recurring revenue potential, and long-term strategic value already have real (if proxy/estimate-heavy) fields in `profit_oracle.py`; pricing power, scalability, and technical feasibility exist only as narrow fixed proxies; urgency, willingness-to-pay, and defensibility had zero code before this round (willingness-to-pay is partially informed by a real keyword-hit signal already computed inside `market_intelligence_engine.py::analyze_customer_pain()`, just never surfaced as its own field before B2 below).
- **Market Validation**: the deliberate decision path (`decision_engine/engine.py::evaluate_and_decide()`) is already genuinely multi-signal (AI-CEO verdict + composite score + real customer-pain evidence). The fully-automatic path (`record_ladder_decision()`, what `market_hunter.py::hunt_market()` actually uses) is honestly single-signal, `ai_ceo_decision` hardcoded `"N/A"` — a real, previously-invisible asymmetry.
- **Product Laboratory**: `revenue_pipeline/plan.py::estimate_pre_acceptance_roi()` already gives a real, informational-only ROI estimate at scoring time — but only ever for one price/ladder at a time, never compared against alternatives.
- **Continuous Evolution**: `evolution_engine.py` is 100% forward-looking (bottleneck/tech-debt/ROI-ranking/capability-gap signals, never a retroactive product-improvement loop). Zero real customer feedback channel exists anywhere (`production_evidence/record.py`'s own code says so). Zero real sales (`data/sales_ledger.jsonl`: 0 `sale` events; `finance_data.json`: 0-length `sales` array) — confirmed unchanged as of 2026-07-22.

## Track A — wire existing real signals

**A1. Defensibility signal** (`profit_oracle.py::_score_defensibility()`). Additive-only field on `score_opportunity()`'s output, propagated through `opportunity_score()`/`ladder_opportunity_score()` — same pattern as `ADR-039`'s Risk/Confidence (never touches `profit_score`/`verdict`, proven by test). Source: `competitor_discovery.py`'s cached `data/competitor_database.json` only — reads a niche's already-discovered competitor classification distribution if present (crowded with Direct Competitor/Enterprise Leader entries → lower defensibility; none → higher), honestly `Unknown` when nothing is cached yet. Deliberately never triggers a live competitor search from inside scoring.

**A2. `decision_path` surfaced in Mission Control.** The field already existed (`decision_engine/types.py::Decision.decision_path`, defaulting `"ai_ceo_full_evaluation"`, explicitly set to `"ladder_fast_gate"` in `record_ladder_decision()`) but was never shown. Added as a badge to the `opportunity-queue` and `unified-priorities` tables — zero new backend logic, makes today's honest single-vs-multi-signal asymmetry visible.

## Track B — build small and honest

**B1. arXiv connector** (`multi_source_intelligence/connectors/arxiv.py`). Free, keyless, official API (`export.arxiv.org/api/query`, ToS explicitly permits this use — unlike Reddit/Product Hunt). Returns Atom XML, not JSON, so a new `market_intelligence_core.http_client::http_get_text()` primitive was added alongside the existing `http_get_json()`; XML parsing uses stdlib `xml.etree.ElementTree`, no new dependency. `SOURCES` grew from 10 to 11; `coverage.py`'s `evidence_coverage_score()` needed no changes (iterates `SOURCES` dynamically). Verified with mocked unit tests (zero live-network dependency in the suite) plus real XML-parsing coverage. A live smoke test against the real API on this machine failed with an SSL certificate error specific to `arxiv.org`'s certificate chain (confirmed: `google.com` and `api.github.com` work fine on the same machine/interpreter) — a local environment gap, not a connector defect; the connector degrades honestly (`unavailable_result` with the real error message) exactly as designed.

**B2. "Go Deep" on-demand evidence action** (`mission_control_api.py::_go_deep_evidence()`, `ACTION_REGISTRY`'s `go-deep-evidence`). For one founder-selected niche, runs 3 already-real, independent evidence sources — `market_intelligence_engine.analyze_customer_pain()` (real GitHub Issues + HN Algolia, including the real `willingness_to_pay_hits` keyword-count signal), `competitor_discovery.get_or_refresh_competitors()` (live classification, unlike A1's cache-only constraint — this tool is explicitly the on-demand deep-dive), and `multi_source_intelligence.coverage.evidence_coverage_score()` (all 11 connectors). Async job (real live-network calls, ~15s observed), same job/polling pattern as `rerun-market-analysis`. Verified live end-to-end: real GitHub Issues found and scored, real HN+GitHub competitor classification returned, real 11-source coverage computed (3/11 succeeded in this environment: hacker_news/github/stack_overflow — arxiv unavailable here for the same cert-store reason as B1). Never gates any decision — purely informational, same discipline as the ROI estimate.

**B3. Product Concept Comparison** (`revenue_pipeline/plan.py::compare_ladder_variants()`, Mission Control's `product-concept-comparison` service). For one niche, computes a real variant per ladder rank (default: all 6) via `profit_oracle.ladder_opportunity_score()` (real demand/competition/margin + documented per-ladder recurring-revenue/reusability constants) and `estimate_pre_acceptance_roi()` (real logged AI cost + real platform fees), sorted by score for readability only — never auto-selects a winner. Fast/local (no live network), so a plain synchronous query-param service rather than an async job. Verified live: correctly priced ai_saas/b2b_systems in the elite band ($174) vs. automation_tools/reusable_assets in premium ($96) vs. educational/kdp_books in book ($45) for the same real niche, each with its own honest accept/reject verdict and real ROI.

A regression was caught and fixed before commit: `product-concept-comparison`'s handler initially rejected (500) when called with no `?niche=` query param, breaking `tests/test_api_contract.js`'s blanket "every service returns 200" contract test. Fixed by returning a real, honest 200 response explaining the missing parameter (matching `knowledgeBaseService`'s existing optional-query-param convention) rather than erroring — the correct, established pattern for an optional-input service in this codebase.

| Urgency scoring dimension | No real data source identified (needs deadline/funding-window/regulatory-trigger detection) | A real signal source is found |
| Willingness-to-pay as its own scoring dimension | A real keyword-hit proxy exists inside `analyze_customer_pain()` (now surfaced via B2) but isn't yet folded into `profit_oracle.py`'s formula, and zero real sales exist to validate any weighting against | First real sales exist, or the founder wants the existing proxy promoted into the formula despite that |
| Real AI SaaS / B2B Systems software-building product adapters (actual hosted apps, not PDFs) | Confirmed still blocked on infrastructure that doesn't exist — hosting, user DB, subscription billing, ongoing support (`ELITE_ASSET_DOCTRINE.md`, 2026-07-13, still true today) | Founder explicitly commits to building real hosted-software infrastructure |

The real plumbing already exists and needs no new schema (`channels/ledger.py`'s `sale` event type) | First real sale exists to build/test the loop against |
| Multi-concept generation via actually drafting multiple full products (vs. B3's parameter variants) | Disproportionate generation cost/complexity for a Round 1 MVP | B3 proves valuable and the founder wants to go further |
