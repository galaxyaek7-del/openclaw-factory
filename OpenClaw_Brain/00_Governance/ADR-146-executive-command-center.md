# ADR-146 — Executive Command Center

**Date:** 2026-07-30
**Status:** Adopted.

---

## The directive

"EXECUTIVE DIRECTIVE — Galaxy Forge Executive Command Center (CEO Mission Control)." Transform Mission Control into a Bloomberg/Palantir/Stripe/Linear-grade "operating system of the CEO": 10 named sections (Executive Overview, Executive AI Council, Opportunity Radar, Revenue Command Center, Production Factory, Market Intelligence, Executive Decisions, Knowledge Graph, Automation Center, Strategic KPI Wall), a Ctrl+K command bar, real-time refresh, responsive/accessible design. Explicit, repeated rule: "No placeholders. No mock data. No fake metrics. Every panel must connect to a real system service whenever available."

## The real tension, surfaced before any code was written (Plan Mode)

Direct code search (not assumption) found several requested panels have **zero real backing data anywhere in this factory today**: no MRR/ARR/cash/runway concept exists anywhere in the repo (`finance_data.json` only holds per-sale/per-platform totals); country-level market data was explicitly deferred by the founder's own 2026-07-23 decision (cited identically across 5 independent real functions); no Enterprise/Subscription/Licensing/API revenue channel exists (real revenue is KDP/Etsy/Gumroad/Paddle only); no worker pool or job queue exists (`lib/health_checks.js`'s own real `not_applicable` classification — a single Express process, `ACTION_JOBS` is an in-memory polling map, not a durable queue). This factory's own standing discipline — real data where it exists, an honest disclosed gap where it doesn't — is the literal thing this directive's own "never fabricate" rule demands, not a compromise against it.

A background research pass (62 real `SERVICE_REGISTRY` entries + 69 real `ACTION_REGISTRY` entries, 131 total — corrected from an initial 150+ estimate) additionally found neither real "AI executive" roster (Executive Board's 10 roles, Galaxy Council's 9 members) carries a live "current task"/"latency" field — both are computed fresh, on demand, against one specific niche, not a continuously-running roster with standing state. Two founder decisions were confirmed via `AskUserQuestion` before building: show Galaxy Council's real member names (not the directive's invented labels); ship plain, dense, real numeric tiles in this round, with real inline sparkline charts deferred to a fast-follow once enough real time-series data exists to make a trend line honest rather than a 2-point stub.

## What was built

**Reused, not rebuilt**: `mission_control_executive_v1.html` (836 lines pre-existing) already had a dark theme, ~45 real panels, and — confirmed before building anything — a mature honesty system (`isMeaningfullyEmpty()`/`confidenceFor()`), **already** did partial per-section DOM updates and 60s polling with tab-hidden pause (the directive's "never refresh whole page"/"real-time... otherwise polling" requirements were already met), and `renderKV()` **already** auto-detects real numeric fields and renders them as dense `.stat-row` tiles. `mission_control.html` (the separate, older, per-niche interactive surface) is completely untouched.

**New real backend pieces** (both read-only, both reuse existing real functions verbatim):
- `market_intelligence_source_status()` (`mission_control_api.py` + `server.js`'s new `market-intelligence-source-status` service) — reuses `multi_source_intelligence.registry.get_connectors()` directly. Static-unavailable sources (reddit/product_hunt/google_trends — confirmed none of the three touches its own `niche` argument before returning) are cheaply checked with zero live network cost; real live-capable sources (hacker_news/github/etc.) are listed as registered without being triggered, avoiding an accidental live call from a passive dashboard read — the same discipline `research_department.py` already established.
- The existing `checks.sensing_engine` (n8n live reachability, already computed inside `computeHealthStatus()`) is cross-referenced in the Automation Status panel's own note rather than duplicated as a second check — it was already reachable inside the existing `company-health` payload, just not visually prominent.

**Frontend reorganization** (`mission_control_executive_v1.html`): all 45 pre-existing sections were tagged with a `group` field mapping to the directive's 10 named sections (plus an 11th, disclosed "Customer Operations" group — 6 real, working customer panels exist and dropping them to hit an exact count would have discarded real data, not honored "never fabricate"). `initGroupContainers()` pre-creates each group's DOM wrapper in the founder's requested order, independent of which section happens to fetch first. 5 new sections were added: the one new real service above, and 4 explicit, statically-labeled "honest gap" tiles (`kind:'static'`, no network fetch at all) for MRR/ARR/Cash/Runway, Enterprise/Subscription/Licensing/API revenue, the country-level opportunity map, and Workers/Job Queues — each citing its own specific real reason and evidence, never a blank or a fabricated zero passed off as measured.

**Command bar** (Ctrl+K / Cmd+K, plus a visible topbar button since automated Ctrl+K can be intercepted by browser chrome): real client-side navigation to any of the 50 sections via fuzzy search, plus a curated subset of 13 real `ACTION_REGISTRY` entries. No literal "Deploy"/"Restart" — confirmed no real backing action exists anywhere in this factory for either. Actions needing a real parameter (niche, proposal_id, reason) prompt inline for exactly that field before firing anything; `reversible:false` actions (a real, permanent founder decision, per `server.js`'s own existing flag) are visibly tagged "Permanent." Escape at any point cancels without side effects — verified live: canceling a pending `risk-intelligence-scan` param prompt never calls the real endpoint.

**Accessibility/responsive**: `:focus-visible` outlines on every interactive element (dark-theme-appropriate, since browser defaults are often invisible against this palette); `role`/`aria-*` attributes on the command palette (`role="dialog"`, `role="listbox"`/`"option"`, `aria-expanded`/`aria-haspopup`/`aria-controls`) and the mobile menu toggle; group headers use `role="heading" aria-level="2"` rather than a real second `<h1>` (the page already has one real `<h1>` for its title — multiple competing `<h1>`s would have been a real semantic regression). Solid basics, not a full WCAG audit — disclosed as such, not claimed as complete.

## Verified live

Full page load against real factory data via a real logged-in browser session on a disposable local server (not just curl): all 10 groups render in the correct order with real content, the new `market-intelligence-source-status` panel shows 11 real registered connectors, the 4 honest-gap tiles render their real static reasons with a distinct "Not Tracked" badge, `Executive Score`'s real sub-scores render as stat tiles exactly as `renderKV()`'s pre-existing numeric-detection logic already does for every other panel, zero browser console errors after a full fresh reload. Command palette verified end-to-end: open, fuzzy search (both navigation and actions), parameter collection, safe cancellation, close. Mobile-width visual verification was attempted but the browser-automation resize tool did not visibly constrain the viewport in this environment — the responsive CSS reuses the exact same `@media (max-width: 880px)` breakpoint this file's own pre-existing, already-production sidebar-collapse behavior uses, but this specific addition was not independently visually confirmed at mobile width this session; disclosed rather than claimed verified.

## Regression check

`mission_control.html` confirmed untouched (`git status` empty for that file). 110 existing tests across `test_executive_brain`/`test_executive_decision_memory`/`test_evolution_queue`/`test_knowledge_graph` all pass unchanged. `data/*.jsonl` confirmed byte-unchanged by this session's testing (only read paths and temp-path-based tests were exercised).

## What was deliberately not built

WebSocket push (the existing polling architecture already satisfies the real requirement — building a new transport layer for a already-met requirement would have been "no architecture expansion" for no real gain); a real geographic map; MRR/ARR/Runway as tracked metrics; Reddit/Product Hunt/News as *live* feeds (shown as real, honestly-labeled unavailable, not live); Enterprise/Subscription/Licensing/API as tracked revenue; embedding-based semantic search over the Knowledge Graph (only real graph-edge traversal exists — `tool_intelligence`'s own `vector_store_for_evidence_corpus` proposal remains un-actioned); a full WCAG accessibility audit; real inline sparkline charts (deferred fast-follow per the founder's own confirmed decision); literal Deploy/Restart command-bar actions.
