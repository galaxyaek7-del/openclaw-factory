# دليل عرض ديمو مساعد وكالات العمرة (للمؤسس)

الحالة: **SIMULATION**. وكالة وهمية وبيانات وهمية. لا شيء مربوط بواتساب أو بأي هاتف (**NOT CONNECTED**)، ولا يُرسَل شيء لأي شخص. المحرك بلا نموذج لغوي وبلا إنترنت: لا يستطيع اختراع سعر، لأن كل رقم يأتي من ملف الوكالة `services/umrah_assistant/agency_example.json`.

## الملفات

| الملف | ما هو |
|---|---|
| `services/umrah_assistant/demo/index.html` | **الديمو**: ملف واحد يعمل بلا إنترنت، واجهة تشبه واتساب، عربي/دارجة/فرنسي |
| `services/umrah_assistant/engine.js` | المحرك (يفهم اللغة والنية، يجيب من بيانات الوكالة، يحوّل للمالك) |
| `services/umrah_assistant/agency_example.json` | بيانات الوكالة الوهمية (باقات، أسعار بالدينار، مواعيد، وثائق، خطوات الحجز) |
| `docs/umrah_demo/ONE_PAGER.pdf` (و`.html`) | ورقة العرض، صفحة واحدة عربي + فرنسي. المربعات الصفراء تملؤها أنت (اسمك، هاتفك، مدة التجربة والسعر) |
| `docs/umrah_demo/PRICING_PROPOSALS.md` | ثلاثة اقتراحات أسعار بالدينار. القرار لك |
| `docs/umrah_demo/OBJECTIONS.md` | أهم 10 اعتراضات من أصحاب الوكالات مع الأجوبة |
| `services/umrah_assistant/onboarding.html` | نموذج محلي (بلا شبكة) لتعبئة بيانات وكالة حقيقية، يتحقق منها ثم ينزّل ملف JSON |
| `tests/test_umrah_assistant.js` | 23 اختباراً (`node --test tests/test_umrah_assistant.js`) |
| `tests/test_umrah_onboarding.js` | 7 اختبارات للنموذج ومخطط البيانات (`node --test tests/test_umrah_onboarding.js`) |

بعد أي تعديل على المحرك أو البيانات: `node services/umrah_assistant/build_demo.js` يعيد بناء `demo/index.html`.

## كيف تعرضه من هاتفك (طريقتان)

**أ. ملف على الهاتف (الأسهل، يعمل بلا إنترنت).** أرسل `demo/index.html` لنفسك (Telegram "الرسائل المحفوظة" أو واتساب لنفسك أو كابل USB)، ثم افتحه بمتصفح الهاتف (Chrome). إن فتحه تطبيق آخر فاختر "فتح بمتصفح".

**ب. عبر شبكة الواي فاي المنزلية (الحاسوب والهاتف على نفس الشبكة).** في نافذة Claude Code:

```
! python -m http.server 8088 --bind 0.0.0.0 --directory services/umrah_assistant/demo
```

ثم في متصفح الهاتف: `http://192.168.1.5:8088/` (عنوان حاسوبك الآن؛ قد يتغير، تحققه بـ `ipconfig`). إن ظهرت نافذة جدار حماية Windows فاضغط "السماح" للشبكات الخاصة. للإيقاف: Ctrl+C. هذا خاص بشبكتك فقط ولا يُنشر للعموم.

لا أنصح برابط عام الآن: نشر شيء للعموم يحتاج قرارك (قاعدة حمراء)، وصاحب الوكالة يكفيه أن يرى الديمو في يدك.

## روابط تشغيل تلقائي (مفيدة أمام صاحب الوكالة)

أضف في آخر الرابط: `?demo=fr` (مثال بالفرنسية) أو `?demo=dz` (بالدارجة) أو `?demo=zz` (دارجة بحروف لاتينية). تُشغَّل محادثة كاملة بنفسها حتى بطاقة صاحب الوكالة. وفي الصفحة أزرار `▶ Démo FR` و`▶ عرض بالدارجة` و`▶ Démo arabizi` تفعل الشيء نفسه.

## سيناريو عرض في 3 دقائق

1. أعطِ الهاتف لصاحب الوكالة واطلب منه أن يكتب كزبون، بلغته: "شحال سعر العمرة؟" ثم "واش لازم من وثائق؟".
2. اطلب منه أن يجرّب "غالي بزاف": سيرى أن المساعد **لا يخفّض ولا يساوم** ويعرض تحويله إليه.
3. اطلب منه أن يكتب "نحب نحجز": المساعد يسأل الباقة وعدد الأشخاص والاسم والهاتف.
4. اضغط الزر `👤 صاحب الوكالة` أعلى الشاشة: **هذه البطاقة هي ما سيصله فعلاً** (اسم، هاتف، باقة، أشخاص، مبلغ تقديري، لغة، آخر رسائله).
5. اختم بسؤال: "كم رسالة تصلك في الليلة ولا تردّون عليها؟" واستمع. لا تعد بأرقام مبيعات: لم يُقَس شيء (**NOT MEASURED**).

## ما هو حقيقي وما هو غير موجود بعد

| البند | الحالة |
|---|---|
| المحرك (لغة، نوايا، حجز، تحويل، رفض التفاوض والشكاوى وأسئلة المناسك) | مبني ومُختبر (23 اختباراً) |
| بيانات الوكالة | **SIMULATION** (وهمية) |
| الديمو على الهاتف | مبني، جُرّب بمتصفح Edge بلا واجهة، لم يُجرَّب على هاتفك بعد |
| الربط بواتساب | **NOT CONNECTED**. واتساب Business API يحتاج حساباً معتمداً من Meta ومزوداً مدفوعاً: قرار ومال، فلا أبدأه |
| رابط محادثة عام تضعه الوكالة في صفحتها | **NOT BUILT** (يحتاج استضافة؛ نشر للعموم بموافقتك) |
| وصول بطاقة العميل إلى صاحب الوكالة فعلاً (تنبيه Telegram مثلاً) | **NOT BUILT**. يستفيد من إعداد Telegram (F5) الذي ستنفذه |
| نموذج إدخال بيانات وكالة حقيقية | **BUILT (محلي)**: `services/umrah_assistant/onboarding.html` ينزّل ملف JSON؛ الفحص المرجعي `validate_agency.js`. التخزين/الرابط العام ما زالا **NOT BUILT** |
| الخصوصية وحماية بيانات الزبائن عند التشغيل الحقيقي | **UNKNOWN / غير محسوم**: يلزم قرار قبل أي زبون حقيقي |
| فهم الدارجة المكتوبة بالحروف اللاتينية أو بأخطاء إملائية كثيرة | مبني بقوائم كلمات وليس ذكاءً مفتوحاً: سيخطئ أحياناً ويحوّل لصاحب الوكالة بدل التخمين. جرّب بنفسك وأخبرني بما فشل |

## ديمو مخصّص لوكالة حقيقية (أقوى ورقة بيع: يرى أسعاره هو)

1. اجمع من صاحب الوكالة المعلومات في القائمة أسفل هذا القسم (يكفي واتساب أو ورقة).
2. انسخ `services/umrah_assistant/agency_template.json` إلى `services/umrah_assistant/agencies/اسم_الوكالة.json` (هذا المجلد لا يُرفع إلى git لأن فيه بيانات زبون).
3. استبدل كل `REMPLIR` بما أعطاك. الأسعار للشخص الواحد بالدينار، أرقام صحيحة.
4. تحقق: `node services/umrah_assistant/validate_agency.js services/umrah_assistant/agencies/اسم_الوكالة.json` (يكشف الحقول الناقصة، أخطاء الأسعار والتواريخ، أو ترك علامة REMPLIR).
5. ابنِ الديمو: `node services/umrah_assistant/build_demo.js --agency services/umrah_assistant/agencies/اسم_الوكالة.json --out services/umrah_assistant/agencies/اسم_الوكالة_demo`. يرفض البناء إن بقي خطأ، فلا يخرج ديمو بمعلومات ناقصة.
6. أرسل `index.html` الناتج لصاحب الوكالة (أو أعرضه من هاتفك). الشريط الأعلى يقول له صراحة: «نسخة تجريبية لوكالتكم، بياناتكم كما زوّدتمونا بها، غير مربوطة بواتساب بعد».

اطلب من صاحب الوكالة أن **يراجع** الأسعار والوثائق في الديمو قبل أي استعمال: المساعد يكرر بالضبط ما كتبته.

## ما يلزمني من صاحب الوكالة الأولى (إن قبلت التجربة)

باقاتها وأسعارها الحقيقية، مواعيد الرحلات، الفنادق ومسافاتها، الوثائق التي تطلبها هي، التسبيق وطرق الدفع، ساعات العمل، رقم استلام التنبيهات. هذه الأرقام هي التي سيجيب بها المساعد، ولا يجيب بغيرها.
